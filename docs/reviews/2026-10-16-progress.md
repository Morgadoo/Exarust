### Pace

terrain, painted apparel, ragdoll, muscles, the render pipeline. Days 2 and 3
were almost all narrow commits named "…as the original does", each replacing
an approximation with the original's rule taken from the decompiled code.
For a fidelity goal that is the right shift. It also explains why the coverage
figure moves slowly: replacing an approximation with the real behaviour does
not add new components. Over 14 commits it gained 0.7 points.

## What helps accuracy

1. **Rules come from reverse engineering, not guesses.** Physics constants,
   damage rules, balance, sleep and muscle gains are taken from the decompiled
   `Exanima.exe` via REA/Ghidra and written up in `context/re/`, with
   addresses and the open questions (Q1–Q12) settled in the decompiled code.
2. **Shortcuts are labelled.** Code that is not the original's says so
   ("Exarust's own", "stand-in"), so known differences can be found with a
   search.
3. **There is a written order of work.** `body-controller-plan.md` lays out
   C1–C23 and S1–S2, and `combat-look-plan-final.md` lays out L1–L14, each with
   dependencies, the questions to settle first, and planned tests.
4. **Tools for comparing with the original exist.** `--trace` writes body
   state per tick in the retail probe's columns; the `retail-exanima` skill
   launches the original with a pinned or free camera; `exa-tool` checks the
   parsers against every shipped file.
5. **Tests pin the rules.** 375 tests, of which 110 are in `exa_physics`.

## Risks to accuracy

1. **Little checking against the running game.** Most "as the original does"
   commits are based on the decompiled code, not on comparing output with the
   real game.
   - C3's notes say "Not done: … a retail comparison".
   - `add-static-mesh-decoding` task 4.2 (a mirroring check in Blender against
     the running game) is still open, and it affects every mesh.
   - Neither the plan nor the code mentions any saved side-by-side
     comparisons, screenshot diffs or trace comparisons.
2. **Temporary code is piling up.** There are about 12 "Exarust's own" sites
   in `exa_physics` alone, plus others:
   - the capsule that carries the body (`body.rs`, `body_lift.rs`,
     `body_muscle.rs`, `body_balance.rs`);
   - the stair-climbing stopgap (`body_climb.rs`, merged in `a4d04d8`);
   - the fall and get-up (`exa_game/src/balance.rs`);
   - the swing-stall stand-in (`exa_combat/src/lib.rs:406`);
   - the duellist with made-up rules (`exa_ai/src/lib.rs:56`);
   - Bevy's atmosphere standing in for the original's sky
     (`exa_world/src/environment.rs`);
   - stand-in start positions (`exa_world/src/grid.rs:519`,
     `exa_world/src/lib.rs:64`).

   Each one will have to be torn out later and can hide differences from the
   original in the meantime. Stairs already regressed with C8.
3. **The coverage figure is an estimate.** It is a byte-weighted rating made
   by AI agents (a rater, an adversarial verifier and a critic). The method is
   careful, but it measures a judgment of the code, not observed behaviour.
4. **Some deliberate departures:** saves will use Exarust's own format (the
   original's are not a compatibility goal), and the sky uses Bevy's
   atmosphere until the original's sky shader is decoded.

## Recommendations for maximum accuracy

1. **Make checking against the original a requirement.**
   - Script a set of scenarios: idle, shove, fall, get-up, a blow, walking,
     stairs, and a few fixed camera shots per level.
   - Run each in both games. Compare the `--trace` output with the retail
     probe within set tolerances, and compare screenshots from the same
     pinned camera.
   - Keep the results under `context/re/` and summarise the tolerances in
     the specs.
   - A change should not count as "as the original does" until it passes,
     or until it states why it could not be checked.
2. **Remove the temporary code before adding more.** Finish the body chain
   C9 → C14 (stance pins) → C18 (walking by the carry) → C19 (walking on the
   gait feet), with C10, C11, C15 and C17 alongside. That retires the
   capsule, the stair stopgap and the made-up fall and get-up. The plan treats
   M3, the "standing man" milestone, as reached after C18.
3. **Close the static-mesh mirroring check** (`add-static-mesh-decoding`
   4.2) now. It is cheap and would rule out an error that touches every mesh.
4. **Before AI work (Phase 6), finish the body work C21–C23** (strike with
   weapon bodies, feel impacts, knock-out and collapse). The original's NPCs
   drive the same body inputs as the player, so faithful AI depends on a
   faithful body.
5. **Tidy up:** push `main` and let CI run; rebase and merge C9 and the
   wall-hollows branch; delete the stale worktrees and branches.
6. **Re-rate the coverage map after each batch of changes** and keep a dated
   history of the headline figures, so progress can be tracked over time.

## Summary

The foundations are solid: all asset formats decode, and the original's
renderer and body solver are rebuilt from the decompiled code, with a
disciplined spec-driven process. About 14 % of the original is reproduced.
The biggest remaining accuracy risk is not missing features but behaviour
that has not been checked against the running game, plus a growing amount of
temporary non-original code.
