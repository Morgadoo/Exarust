# Chunk trees (`.rfc`): meshes, materials, levels

Status: **verified** for the container, scene node headers, static meshes
and material texture layers (`exa_formats::rfc`, `exa_formats::material`).
Level sections are still **observed** only.

Evidence: the reader in `Exanima.exe` 0.9.5 was examined with REA (Ghidra
12.1.4), and `cargo exa corpus meshes` decodes all **23 065** mesh records in
7 653 retail files with 0 failures. Sample exports (props, a door frame, a
chest, a weapon part) checked in a glTF viewer at real-world sizes.

## Container

```
u16 sanity   0xAFCF
u16 version  0x3D23 (retail); 0x3D21 on 3 meshes in Characters.rpk
chunk*       root chunks until end of file

chunk: u32 tag, u32 size, u8 payload[size]
```

Root chunks: `0xBA00` material list, `0x3D000000` scene node list, and in
level files `0x3DED` tile grid, `0xDBC0` local database (items, strings,
placement), `0x3DE10000` props, `0xCAC00001` characters, `0xEC00DC00`.
Unknown root chunks are skipped by size.

Counts follow two conventions: list chunks (`BA00`, `3D000000`) store the
count; counts inside a mesh store **count − 1**.

## Material list (`BA00`)

`u32 count`, then `count` chunks (`BA01`): `name[16]` followed by a material
payload. The same payload is the value of an entry in an `.rml` library.

Payload: a 184-byte block of shading parameters, then 56-byte texture
layer records. Of the block, the colours, opacity, gloss, specular level,
render class, flags, kind, extra flags, displacement and opacity fall-off
are read for shading (`docs/RENDERING.md`), and two fields for physics
(REA on the original's material constructor and loader; corpus below):

| off | field |
|---|---|
| `0xA4` | `f32` physical divisor: a rigid body on a node whose first mesh part has this material registers with its stored mobility divided by it; the loader reads 0 as 1 (the constructor's default) |
| `0xAC` | `char[4]` impact sound prefix (zero-padded); empty, the material name's first 3 characters stand in. The impact sound set is the prefix followed by `col` (`mtliron04` → `mtlcol`) |

Divisors of the first material of every body node: `Objects.rpk` 1 230
bodies, 1 (stored 0 or 1) ×1 144, 0.5 ×21 (cushions), 2 ×33 (`mtliron03`),
3 ×32 (`mtliron04`); `Objlib.rpk` 1 503 bodies, 1 ×1 297, 0.6 ×11 (wicker
`wkrtl01`), 0.8 ×2, 2 ×76, 3 ×102, 10 ×15 (`xaresdevbrass`): iron moves two
to three times less than wood. Most prefixes are empty; the others are
`stn`, `wdl`, `mth`, `MtlM`, `cer`, `clt`, `fls`, `wod`, `wkr`, ….

Texture layer records:

| off | field |
|---|---|
| 0 | `u32` slot flag |
| 4 | `u32` record length (56) |
| 8 | parameters (layer amount, tint, …) |
| 40 | `name[16]` texture entry, sometimes with `.rfi`/`.dds` |

| slot flag | role (from texture-name suffixes) | uses |
|---|---|---|
| `0x00020000` | diffuse (`d`) | 7 284 |
| `0x00200000` | normal (`n`) | 6 733 |
| `0x01000000` | gloss (`g`) | 4 771 |
| `0x00800000` | height (`h`) | 2 126 |
| `0x00040000` | specular (`s`) | 1 588 |
| `0x08000000` | ? (names without suffix) | 1 572 |
| `0x00100000` | reflection (`r`) | 1 237 |
| `0x00400000` | detail / second diffuse | 261 |
| `0x00080000` | emissive? | 44 |

7 639 of 7 648 payloads follow this layout; 9 material lists in level and set
files do not and are reported. 88 % of referenced texture names exist in the
retail packs; the rest are absent from the shipped data.

Materials are looked up by name: the file's own list first, then the
libraries named in `Exanima.rfp` (`common`, `underworld0`, `underworldb`),
plus `humanbase.rml` for characters. Weapon parts carry no materials (their
look is generated by the weapon factories).

## Scene nodes (`3D000000`)

`u32 count`, then one chunk per node; the chunk tag is the node kind:
`0x3D03` mesh, `0x3D06` light, `0x3D0C` voxel light, `0x3D08`, `0x3D0A`,
anything else a plain node (`0x3D01`).

Header, shared by every kind:

```
char name[16]
u32  flags         top 20 bits stored; low 12 bits are a class id (0x89 for meshes)
u32  flags2
u32  instance      non-zero: the node reuses other data and stores nothing more
u32  parent        1-based index into the node list; 0 = root
f32  matrix[12]    3x4 row-major: three rotation rows, then translation (cm)
f32  extent[3]      the box's half extents (cm, node space)
f32  centre[3]      the box's and the sphere's centre
f32  radius
u32  ?
```

The box is the mesh's vertex bounds: for every one of the 103 plain weapon
models of `Objects.rpk`, centre.y + extent.y is the highest vertex to
0.05 cm. The original keeps centre and half extents on the node and
measures weapons by them (`OTHER.md`, Weapon record).

The body depends on the kind (a mesh's below; a light's 40 bytes, 8 more
for a spot and 16 more under its body flags `0x30000`; a voxel light's 32;
`0x3D08`'s 8; none for the others); after it come optional sub-chunks, for
every node that stores data, whatever its kind (an instance stores none):
`0x3AC1` keyframe track, `0x3D0CEC04`, `0x3D0CEC05` GI points,
`0x3DD0B001` rigid body, `0x3DD0C001` cloth marker, `0xEDC0C589` morph
blob, and on plain nodes the emitter records (`0x3DD0E002` fire,
`0x3DD0E004`). The original reads them in one loop after the body of any
kind (REA on the node reader); walking them after every kind's body ends
exactly at each node's end in every chunk tree of the installed packs.
Exarust reads the GI points of meshes, the rigid body
(`Node::rigid_body`, below), the cloth marker (`Node::cloth_marker`) and
the keyframe tracks (`Node::key_tracks`) after any kind's body, and a
mesh's morph set (`Node::morph`, below); the others are skipped for now. Shipped, by node kind: on meshes 10 729 GI point
sets, 874 `0x3D0CEC04`, 2 782 rigid bodies, 17 cloth markers, 2 morph
blobs and one keyframe track; on plain nodes 28 fires and one
`0x3DD0E004`; nothing after lights and voxel lights. Every rigid body and
cloth marker sits on a mesh node.

## Mesh body (`3D03`)

```
u32 ?                         only when version > 0x3D21
u32 streams - 1
stream × streams:
  u32 id                      low 16 bits are the key used by index maps
  u32 format                  bits 16..23: F3 vec3, F2 vec2, B4 rgba8, A4 skin
  u32 count - 1
  element[count]
chunk 0x3DC0 topology:
  u32 ?
  u32 vertices - 1            unified vertex count V
  u32 groups - 1
  group × groups: u32 ?, u32 first_vertex, u32 last_vertex, char material[16]
  u32 maps - 1
  map × maps: u32 key, index[V]          u16 when V < 65535, else u32
  chunk 0x3DC1 triangles (optional):
    u32 ?
    u32 triangles - 1
    index[3 × triangles]                  into unified vertices
    per group: u32 first_triangle, u32 last_triangle   (empty group: last = first - 1)
    sub-chunks: 0x3DC2 u8[triangles], 0x3DC3 u32[triangles]   (not decoded)
```

| stream id | format word | content | count |
|---|---|---|---:|
| `0x00000001` | `0x00F30001` | positions | 23 065 |
| `0x00000010` | `0x00F20010` | texture coordinates | 23 064 |
| `0x04000001` | `0x02B40100` | RGBA8 vertex colour (channel order unverified) | 2 708 |
| `0x04000001` | `0x02A41000` | skin: 4 × u32 bone, 4 × f32 weight | 113 |

Index maps link each unified vertex to an element of every stream whose id
has the same low 16 bits: key `…0001` → positions (and the colour/skin
streams), `…0010` → texture coordinates. Key `0x0002` has no stream: it
groups vertices for normal smoothing. Normals are not stored. Exarust
computes them by area-weighted accumulation per smoothing group.

Orientation: floor modules (`gefs_*`) lie at y = 0 with every horizontal face
pointing +Y under right-handed, counter-clockwise winding, and floor modules
are 300 × 300 units. Geometry is therefore centimetres, right-handed, Y-up,
CCW fronts, the same as glTF after scaling by 0.01. Mirroring relative to the
running game has not been checked yet.

Level geometry faces outward, floors up (`exa-tool corpus winding`: the 29
levels' own meshes and 79 935 props in the world, the 1 619 pieces of the 36
grid sets they use in the piece frame, as Exarust builds its one-sided level
colliders). Of the near-horizontal (|n.y| > 0.7) grid-floor triangles (floor
sets and `+F…` strips), 98.6 % face +Y; the downward rest are the undersides
of grates, pit lips and trim strips, except `gews_ubb02` `+TCD23.200`'s strip
`+FTC00.210`: 50 triangles, all facing down (the trim selection of the grid
builder places it once, in `exanima08`). Over walls, level meshes and props
62.7 % of 21.2 M face up and 90.6 % of the downward ones are the bottoms of
solids (the first face of the object above them faces up); open downward faces
below 2 m are 2.7 %, mostly rock overhangs and foliage. Ceiling pieces (`+R…`)
are black caps facing up (80.6 % of their horizontal area), not downward
ceilings. No node and no prop placement is mirrored (negative determinant).
`_null` groups (254 229 triangles, half of the horizontal ones up) are neither
drawn nor built.

Textures pair with texture coordinates unchanged when images keep their
stored (bottom-up) row order.

## Rigid body (`3DD0B001`)

Status: **verified** (REA on the original's reader and writer of the chunk;
every body of every pack decodes). A mesh node carrying this sub-chunk
becomes a four-particle rigid body in the original: a plain body, or a
door, lever or push surface when the object database record that placed
the model says so (`OTHER.md`, Door and operative sections). Exarust decodes
it into `rigid_body::RigidBody` (lengths in metres).

```
u32  class          0x10000000 on every body; 0x400, 0x8000, 0x8 on some
f32  mobility       how easily it moves (larger moves more)
f32  rest[4][3]     the particles' rest points (cm, node space)
f32  masses[4]      point masses: 4 / the centre of mass's barycentric weight
f32  friction       0.75 in every shipped body; skipped by the reader
f32  1.0, u32 0, u32 group mask, u32 ?   skipped by the reader
then sub-chunks (u32 tag, u32 size, payload) to the end:
  0xCD00  u32 0, u32 count, count × f32[4]  spheres: centre (cm), radius (cm)
  0xDDB0  u32 count, count × link
  0xDDB3  u32 count, count × sound slot
link:  u32 flags, f32 on_body[3], f32 on_parent[3] (cm), f32 slack, f32 strength,
       f32 smoothing, and f32 axis[3] (cm) when flags & 4 (a slider)
sound slot: u32 id, f32 point[3] (cm), char sound[16], f32 volume, f32 pitch
```

The original ignores the stored friction (bodies keep 0.75) and forces the
group mask to 0. It divides the mobility by the physical divisor of the
node's first mesh part's material when it registers the body (Material
list, `0xA4`).

**Registration** (REA on the original's registration, its sector walk and
the body set-up; Exarust: `exa_physics::body::Ragdoll::rigid`,
`exa_world::bodies`). A node whose body is not marked static (node flag
`0x80000`: a level's own node can store it, as `arenao1`'s tavern table
does with flags `0x8090089`; a prop placed static sets it on all its
nodes; `rfc::Node::is_static`) registers when its level loads, with its
body children (a body under a plain node under a body never registers),
and its whole subtree stops being level collision. It registers **asleep** (sleep countdown 0) with its four
particles at the node's world matrix × the rest points, at rest. Gravity
acts on particle i by the share wᵢ = 4/mᵢ, scaled so the shares sum to 4
(mᵢ the stored point masses): gravity acts at the centre of mass. The
spheres meet the level with friction 0.75, and other bodies' parts through
the pairs ([RSQ.md](RSQ.md), contacts between bodies): its contact mobility
is its mobility, its group masks come from its tree (a child never meets
its parent), it is in no layer. Exarust keeps its meshes as stand-ins for
the character capsules, which no body meets. A body whose parent node has a
body is an articulated child: its links join it to the parent's body (the
parent point plus the node's local translation; only flag 8 kept, so a
slider becomes plain slack of its stored value), then a pivot from its
origin to that translation (slack 0, strength 1), every correction shared
m/(m + m_parent) by the two mobilities. A root body with links hangs from
the world and never meets the level. The body scale stays 1: body props
are placed with unit matrices (to 1 %). A body below −50 m is removed with
its node. Node flag `0x800000` would freeze a body (mobility 0); no
shipped body carries it.

Level counts (`exa_world::bodies` corpus test): `exanima01` registers
4 591 body trees of 5 000 bodies (props, placed objects, its own model);
122 hang from the world, 198 are doors, levers and plates, 492 belong to
props placed static. `arenao1`: 17 register, 3 hang, 68 are static props,
and its own model's tavern table is a node marked static (exanima01's six
tables are not). Exarust registers only the free trees for now (no world links, no
mechanisms yet).

**Links.** A root body's links hold it to its parent node (world links:
hinges, axles, slider rails); a child body's links hold it to its parent's
body (a chain's links, a knocker on a door). Slack is the free distance
before the link pulls, 0 for a pin. **A slider stores its travel squared**:
every one of the 33 slider links shipped (11 bodies: buttons 7 cm, pressure
plates 4 cm, the portcullises 170 and 190 cm, a flood gate 252.4 cm, secret
doors and shelves) has slack = |axis|², so `BodyLink::slack` holds the
square root, the travel; the original divides a slider's projected offset
by the stored value to get the fraction travelled. Flags 2 and `0x10000`
also appear (54 and 45 links): when it registers the body the original
clears `0x10000` on a root body's links and keeps only 8 (then sets
`0x10000`) on a child body's.

**Sound slots** are scrape and roll loops played while the slot's point
moves; only the two flails of `Objects.rpk` carry one (`ChnAMov`,
volume 0.5, pitch 1).

Corpus (`exa-tool corpus bodies`): `Objects.rpk` 1 163 of 1 253 models carry
a body (1 230 bodies: class words `0x10000000` 564, `0x10000400` 600,
`0x10008000` 39, `0x10008400` 19, `0x10008408` 8; 1 to 7 839 spheres of
0.96–41 cm; mobility 0.0053 to 316, median 1.83). 69 models carry links: 65
hang from the world (doors, gates, portcullises, levers, buttons, plates,
the hanging brazier, wall lamps, the resonance devices), and two flails and
two scales only link child bodies. `Objlib.rpk` has 1 503 bodies in 1 293
models (89 with links), `Characters.rpk` 12, `Resource.rpk` 37.

Examples: `door uw01a` swings on a top hinge pin at 242.9 cm and a stop of
134.04 cm slack (1 899 spheres, mobility 0.016), with a knocker as a child
body; `lever a01` turns on two axle pins at x = ±15 cm, its arm point at
40 cm held with 33.81 cm of slack; `brazierhang01` hangs by a chain of six
links (6.84 cm of slack each, the first a world link).

## Cloth marker (`3DD0C001`)

One word (0 in every shipped file) after a mesh body. The original gives
the node a cloth controller with its built-in cloth parameters when the
scene the node is loaded into carries flag `0x10000`, which the game's
scene gets when it is created (REA on the chunk's handler and the game
scene's set-up); elsewhere the marker is ignored. Shipped: the two meshes
of each of the six long hair models in `CharExt.rpk` (`hair hula01…05`,
`hair husa02`), four banners in `Objlib.rpk` (`bannerubma01`, `mawbanner01`,
`uw01_banner01`, `uw01_banner02`) and the wraith's robe in
`wraithhabase.rfc`. Exarust reads the marker (`Node::cloth_marker`).

## Keyframe tracks (`3AC1`)

Status: **verified** (REA on the node reader, the track's clock and curve,
the scene's playing list and the object use that starts it; every chunk
tree of every pack, nested packs included, parses). A position track the
original plays on the node's translation:

```
u32  ?              0x3AE2 in the one shipped track; skipped
u32  mode           0 free, 1 once, 2 reverse, 3 loop (any other: free)
f32  duration       seconds
u32  last           index of the last key
key × (last + 1):
  f32 time          seconds
  f32 position[3]   cm: the node's translation in its parent's space
```

Bytes after the keys are skipped with the chunk. A node may carry several
(the original appends each to the node's list).

**Playing.** Nothing plays a track until it is started. The original
starts every track of an object's nodes (the object's root and every
node under it) when the player uses the object: the use of an operative
object of class 0 (the secret switch's class) whose state allows it
starts them, plays its sound and signals its target (after 2.1 s for
kind 1). A start adds each track that is not already playing to the
scene's playing list with the frame clock's time (ms), then swaps its
mode between once and reverse, so a second use plays it back the other
way; a start while it plays does nothing. Every frame each playing track
turns `t = (now − start)/1000` s into a curve time: free as it is; once
min(t, duration), ending at the duration; reverse duration − t, ending
at 0; loop t − ⌊t/duration⌋·duration (a zero duration runs on as free).
The node's translation is set to the curve's position there; a track
that ends leaves the list and its node where it stopped. The clock is
the engine's frame clock (ms of the system timer less the time it skips),
not the 12 ms body-tick clock.

**Curve.** Up to the first key's time the first key's position, from the
last key's time on the last key's; in between, with keys i − 1 and i the
first key at or past t and the one before it, s = (t − tᵢ₋₁)/(tᵢ − tᵢ₋₁)
and the cubic Hermite basis:

```
p = pᵢ₋₁·(2s³ − 3s² + 1) + pᵢ·(3s² − 2s³) + m₀·(s³ − 2s² + s) + m₁·(s³ − s²)
m₀ = 0                                             first segment (i = 1)
m₀ = (pᵢ − pᵢ₋₂)·(tᵢ − tᵢ₋₁)/(tᵢ − tᵢ₋₂)           otherwise
m₁ = (pᵢ₊₁ − pᵢ₋₁)·(tᵢ − tᵢ₋₁)/(tᵢ₊₁ − tᵢ₋₁)       before the last key
m₁ = pᵢ − pᵢ₋₁                                     last segment
```

So the curve leaves its first key with no slope and arrives at its last
along the last chord: not symmetric.

**Shipped.** One track in all the data (`exa-tool corpus tracks`): the
brick of the secret switch (`Objects.rpk` `uwa01 brkswtch`, node `Box001`
under the root `Plane001`, both at the origin; the "Secret Swt Brk"
object, operative class 0 kind 1), mode once, 3 s, keys (0 s, 0 cm),
(1 s, z −5 cm), (2 s, z −5 cm), (3 s, 0 cm): used, the brick sinks 5 cm
into the wall and comes back out over 3 s (−2.19 cm at 0.5 s, −5.63 cm at
1.5 s, −2.81 cm at 2.5 s). The first use plays it in reverse, which the
symmetric keys hide. `exanima03` places the switch in its own database at
(−40.65, 1.93, 83.29) m. The original's other key controller (linear
positions) is never built. Exarust decodes the tracks
(`exa_formats::key_track`, `Node::key_tracks`), and `exa_anim::tracks`
plays them on the node entities `exa_world` spawns; nothing uses objects
yet, so F7 starts every track of the level (`docs/DEBUGGING.md`).

## Morph sets (`EDC0C589`)

Status: **verified** (REA on the race loader, the set's reader, the
character builder's physique pass and the transfer to parts and apparel;
both shipped sets decode). A race's `<stem>morph.rfc` (`humanmorph.rfc`,
and an identical `ancientmorph.rfc`; no other race has one) holds a body
mesh `/00Male_Ba` (2 286 position elements, placed at (0, 102.98, 0) cm,
unturned: where `humanbase.rfc` puts its pelvis) and 18 plain nodes; the
mesh carries the set after its body:

```
i32  n                    landmarks (18)
f32  landmark[n][3]       cm, the body's space: bone k + 1's origin (pelvis at 0)
f32  base[V][3]           cm: each element of the mesh's position stream
i32  t                    targets (11)
target × t:
  f32 landmark[n][3]      cm: how far each landmark moves at weight 1
  f32 position[V][3]      cm: how far each position moves at weight 1
```

V is the mesh's position-stream count; the chunk ends with the last
target. Target roles from their offsets: 0, 2, 3 and 1 the physique
picker's corners (1 broadens hips and shoulders by up to 11.6 cm), 4 age
(a stoop), 5 female (narrower shoulders), 6 its feral extra, 10 height
(the body comes down onto its feet: pelvis 11.20 cm, knees 6.21, head
13.59, feet 0; the standing pelvis's 11.25 cm per unit of height), 7–9
unweighed by a record. `exa-tool morphs` prints both sets.

**Weights** (the builder's physique pass, every target first 0; the
record's height h is kept in −1…1, age a and feral level m in 0…1): x, y
= the two physique values kept in 0…1 (NaN, which the original lets
through, reads 0 in Exarust); x > ½ → ½ + 0.8·(x
− ½); x > 0 → 0.9·x + 0.05·(1 − h); f = 1.5, or 2x + ½ below ½; x −=
¼·m². The picker (only into a set of more than three), y′ = 1 − y: x > ½
→ u = 2x − 1, w1 = (1 − ¼y′)·u, w2 = (1 − ½u)·y′, w0 = w3 = 0; else u =
2x, w0 = (1 − y′)(1 − u), w2 = u·y′, w3 = (1 − u)·y′. Female: w5 = 1, w6
+= ½·m²·f. Then w4 = (1 − 0.3·(w6 + w0))·a, w0 and w4 × (1 − 0.3a), w4 +=
½·m², w10 = h. Physique (½, 1) with h, a, m 0 weighs nothing; a new
record's (0, 0) weighs w3 = 1; past the corner (feral, x near 0) weights
reach 1.5. Over the 126 placed humans and ancients no record weighs
nothing (`exa-tool morphs --records`).

**Applying.** The race's base body parts, and each garment piece when a
character first wears it, get a set of their own from the body (the
transfer): each position element, taken into the body's space, finds the
nearest point of the body's surface within 10 cm and its barycentric
coordinates; its offset per target is that point's blend of the
triangle's offsets, less the offset of the landmark nearest the piece's
origin, turned into the piece's frame. Elements with no surface within
10 cm take, pass after pass, the inverse-distance mean of their
neighbours (each triangle corner's next corner) set before the pass;
those never reached keep minus the landmark's offset. A garment's
pieces sit on the base body part of the bone their node names before
the transfer (their own file frames are the artist's layout). Every
`humanbase.rfc` element finds the surface; each part's nearest landmark
is its own bone's. Per character, positions = base + Σ wₜ·offsetₜ over
targets weighed at least ≈1.2e-7, the piece's box and sphere refitted
(half extents at least 0.001 cm), and each morphed body part's origin
moved by its landmark's Σ wₜ·offsetₜ, its translation recomputed in its
parent's moved frame (rotations kept; a node without a set ends the
walk). This runs before the limb bodies and the motion binder read the
nodes, so physique moves the joints and the links; the dressed mesh is
then skinned on the morphed shape with the morphed joints. Exarust
(`exa_formats::morph`, `exa_assets::morph`) does the same, recomputing
normals from the morphed shape, and skins garments on the unmorphed body
(its own nearest-vertex rule); the original also hands the body's skin
weights to garments through the same mapping (not ported).

## Light node (`3D06`)

Body after the node header: `u32 flags`, `f32 rgb[3]` (linear colour),
`u32 ?`, then five `f32`: a multiplier and an intensity whose product scales
the light (`0.1 × 60`, `1.0 × 1.3`), the radius in centimetres (630–1500),
and two unidentified values (`0`, `0.5`/`1.0`). When `flags2 & 0x300 == 0x200`
two more floats follow, and when `flags & 0x30000` is set, a skipped word and
three floats. `exanima01` has 196 of these lights; arenas have one or two.

## Voxel light node (`3D0C`)

Status: **verified** (REA on the node reader and the GI injection; every
`.rfc` of every pack parses). A voxel light (class `0x41`) is a glow the
original adds straight into its voxel GI volume around the node, never onto
surfaces (see `RENDERING.md`, Voxel GI). Body after the node header, 32
bytes:

```
u32  ?            0 in every node
f32  rgb[3]       sRGB colour
f32  ?            1 in every node, unread
f32  intensity    counts by its square root
f32  radius       cm; the GI injection never reads it
u32  ?            0 in every node
```

The corpus holds 23: four each in `exanima05` and `exanima07`, two in
`exanimac1`, and one in each glowing object's model: `embers a01`
(Objlib), and in Objects the two salves (`jarsalve a01`, `a02`), the power
crystals, `pedestal hand`, `repairsphere a01`, `resdeviceubb a1` and
`teleporterubb a1`. A glowing item pairs it with an unlit additive glow
mesh: the menu's Healing Salve (`JarSalve A01`, placed on the left shelf)
has `@Omni001`, (0.216, 0.678, 1.0) at intensity 16, 3 cm above the jar.
The salves', power crystals' and repair sphere's nodes carry node flag
`0x10`, the others 0 ([?] meaning). `chunk::tag::VOXEL_LIGHT` was called a
mesh tag before.

## Level (`3DED`)

Status: **verified** (REA on the loader; `exa-tool corpus levels` decodes all
29 levels).

Tile-grid dungeons are assembled from modular sets in `Resource.rpk`:
`gews_*` wall sets (`TGEWallSet`) and `gefs_*` floor sets (`TGEFloorSet`).

```
u32  n_wall_sets;  char name[16] × n     "GEWS_UWA01"
u32  n_floor_sets; char name[16] × n     "GEFS_WodPlA1"
u32  width, height                       32×32, 32×40, 64×64, 24×24
u32  legacy_marker                       600 → planes B and C use an older bit layout (converted on load)
u32  ?                                   600 in retail files
u32  plane_a[width × height]             edges and corners
u32  plane_b[width × height]
u32  plane_c[width × height]
```

Plane A packs four 4-bit edge codes in the low 16 bits (top, left, bottom,
right) and four corner codes in the high 16 bits. The engine fills borders
with fixed values (`0x20010007` top row, `0x00120070` left column,
`0x12007000` right column, `0x01200700` bottom row, distinct corner values)
that rotate the codes one nibble per side; `7` is a solid wall edge. Planes B
and C (floor and ceiling data) and the selection of set pieces are decoded in
the grid-builder work.

Set pieces are named `<prefix><type><sub><variant>`: prefix `+` main piece,
`[` attachment; type `W` wall, `C` corner, `F` floor, `R` roof/ceiling,
`T` trim; sub-types such as `CA` centre, `LF`/`RF` left/right, `DF` door
frame, `IA`/`OA` inner/outer corner; a two-digit variant.

## Grid building

Status: **verified** (REA on the builder; `arena` and `exanima01` rebuilt in
Exarust match the original look).

- Cells are 6 m (600 units). Cell `(x, y)` is centred at
  `((x − w/2) + 0.5) × 600, 0, ((y − h/2) + 0.5) × 600`; border cells are
  never built; a cell is built only when plane A has the open flag `0x80000`.
- Plane C: bits 0–3 wall-set index (`F` = no cell), bits 4–7 floor-set index
  (out of range = no floor), bits 8–15 centre-floor variant, bits 16–20
  special tile type, 21–22 its rotation, 23–27 which matching trim to use.
- Plane A: side `i` (0 back/−Z, 1 left/−X, 2 front, 3 right) has edge code
  `(A >> 4i) & 0xF` and corner code `(A >> (16 + 4i)) & 7`; bit 3 of the
  corner nibbles are flags (`0x80000` open cell, `0x800000` terrain cell:
  its floor is terrain, see the cap below and
  [TERRAIN.md](TERRAIN.md), Blocks in grid levels).
- Plane B: the matching 4-bit variant of every edge and corner.
- Pieces are authored for side 0 and rotated by `i × 90°` about +Y (rows
  `[cos, 0, −sin]`, `[0, 1, 0]`, `[sin, 0, cos]`), positioned at the cell
  centre; their stored transform is ignored.
- Wall sets index pieces `+W?nn` (`C` straight, `D` door, `L`/`R` ends),
  `+C?nn` (`L`, `R`, `I`, `O` for corner codes 1–4), `+R?` ceilings (`M`, `L`,
  `R`, `B`, `C` → slots 0–4) and `+T??nn` special tiles; a fourth character
  `B` marks an alternate piece used on sides 2 and 3. Only top-level nodes
  are pieces: `+R…` and `+F…` nodes under a piece are its own strips
  [inferred from the data: all 35 `gews_*` sets hold every piece and slot
  piece at the top level; the only piece-named nodes below are the pieces'
  own `+R…` strips, one `+RBA02` under an occluder in `gews_ubb01`, and a
  `+WCA00` inside a special tile in `gews_usa01` and `gews_uwb06pb`, which
  must not replace the set's straight wall]. Floor sets index `+FM`
  centre variants and `L`, `R`, `B`, `C` edge slots 1–4.
- Per cell: centre floor variant and ceiling slot 0; per side, edge code 0 →
  floor and ceiling slot 3; 7 → straight wall; `B` → door; 1 → left end plus
  slot-2 strips; 2 → right end plus slot-1 strips; 3 → both ends; every wall
  adds slot-3 strips. Per corner, code 0 → floor and ceiling slot 4; codes
  1–4 → corner piece, floor slot 4, ceiling slot 3.
- Special tiles: a mask per type removes the regular pieces they cover:
  `7777FFFF`, `7070FFFF`, `7077FFFF`, `7777FFFF`, `7777FFFF`, `7007000F`
  (types 6–9), `00770FFF`; types 5–8 keep the centre floor.
- Floors are merged into a `+Floor` mesh per cell in the original; walls
  stay separate objects. The ceiling strips also make a per-cell
  `+Ceiling` mesh that is never drawn (its node is marked externally drawn;
  its purpose is not known); what shows of the ceilings is the room's lid
  below.
- Every `+`-material triangle of a cell's floor (the centre variant, the edge
  strips and the pieces' `+F…` strips) gets planar UVs `u = x/600 + 0.5`,
  `v = 0.5 − z/600` in cell-local cm, after the piece's side rotation: one
  square repeat per cell. The stored UVs are discarded. Ceilings, walls and
  non-`+` materials keep their stored UVs.
- Direct children of wall, corner and special-tile pieces are redirected:
  `+F…` is the piece's own floor strip and replaces the floor set's strip on
  that edge (slot 3, or 4 for corners). Its `+` materials take the floor
  set's own `+` material. `+R…` is its ceiling strip and replaces the
  ceiling slot.
- Shells: for a cell in a room, every placed piece's direct `[…` children
  (the occluders: `_black` boxes from the floor to 2.7 m behind the
  facade, more for corners and special tiles; most reach the cell edge,
  but the plain walls and inner corners of `gews_tsa01`, `gews_uwa01` and
  `gews_UwA01p` stop 2.6 m from the cell centre, 40 cm short of it, where
  those sets' floor strips do not reach either) go to the room's occluder
  strips, and its `+R…` children plus the ceiling slot pieces the cell
  selects (flat `_black` at 4 m; a wall's own strip ramps from 4 m 1.5 m
  inside the cell down to 2.64 m at its edge) to the room's ceiling
  strips, in world space. After the grid each room
  has one position-only occluder shell and one ceiling shell (its lid),
  drawn by the room manager ([RENDERING.md](../RENDERING.md), Rooms and
  black fill), never as scene nodes. Some other sets give occluders
  textured materials (`gews_ubb01`) or nest them deeper (`gews_uwb06b`)
  [not checked against the original's builder].
- Ceiling cap: an open cell without a wall set (nibble `F`) whose plane A
  has `0x800000` adds ceiling strips from the first wall set to its room
  (the middle slot; per side, edge 0 → slot 3, walls → the wall piece's own
  `+R…` or slot 3; per corner, 0 → slot 4, 1–4 → the corner piece's own
  `+R…` or slot 3) and builds no wall, floor or occluder. `exanima01` has
  104 such cells; the flag's other 578 cells there have a wall set and
  terrain for floor. Levels without wall sets build nothing from the grid.
- Rooms (the original's flood fill, reproduced exactly for the live
  arena hub: 10 rooms, 18 links, the same room per cell): the seed is the
  first open cell (inside the border) of the last row that has one. Cells
  behind doors wait on a stack of door seeds, last in first out, each
  starting a new room unless a room reached it meanwhile. A room spreads
  over every edge but walls (7) and doors (`B`); a closed cell reached that
  way joins the room without spreading. A door edge records a link (the
  cell, the cell behind it) when the cell behind is open and does not face
  the door with a wall; links into the room itself are dropped after its
  flood. Open cells no door path reaches get no room. `exanima01`: 153
  rooms, 356 links, every open cell in a room.
- Portals: each door link is a portal sized from plane B's side nibble
  (0: 82 × 245 cm, otherwise 115 × 290 cm, special tiles 200 × 340 cm).
- Every level with a grid chunk, the outdoor arenas' (no wall sets)
  included, puts the scene in grid mode, which limits its terrain to the
  terrain cells ([TERRAIN.md](TERRAIN.md)).
- The marker and skip words are 0 and 600 in every level; the builder reads
  only width, height and the planes.

## Environment (`EC00DC00`)

A fixed 248-byte record in every level file (29/29 decode;
`exa_formats::environment`). Only some fields are read by the 0.9.5 runtime:

| off | type | meaning |
|---|---|---|
| 0x00 | u32 | flags: `0x10000` always; `0x20` on the outdoor terrain arenas (effect unknown) |
| 0x04 | u32 | sun mode: 0 auto, 1 off, 2 on (stored; the presets below decide) |
| 0x08 | f32 | sun altitude: 0 down, 0.5 horizon, 1 zenith (default 0.7516) |
| 0x0C | f32 | sun azimuth: 0 towards +Z, growing towards −X, ±1 towards −Z (default −0.21) |
| 0x10 | f32 ×4 | sun colour, sRGB (0.75 grey) |
| 0x30 | f32 ×4 | secondary ambient, sRGB (0.04 grey on most levels) |
| 0x40 | f32 ×3 | **main ambient colour**, sRGB (0.6275 grey, warm on some arenas): the shader's `Ambient` |
| 0x90 | i32 | top of the level's height grid, cm; the loader fills it from 0x98 when it is 0 (arenas 1, 2, 4, 5, 6). The navigation grid's columns reach 25.5 m down from it ([NAVIGATION.md](../NAVIGATION.md)); Exarust also takes it as the highest point when 0x98 is 0 |
| 0x94 | i32 | lowest point of the level, cm |
| 0x98 | i32 | highest point of the level, cm (fog anchor, top of the GI volume) |
| 0xD0 | f32 | added to the reverb decay (1.49 s) |

Other fields (fog colour 0.5, a cubemap name `EnvMapIA01`, …) are stored but
not read. Without the record a level gets ambient 0.314 and extent 0..3.4 m.

Sun direction (Y up, unit vector towards the sun): θ = (1 − altitude)·π,
φ = −azimuth·π, `(sin θ sin φ, cos θ, sin θ cos φ)`. Light travels the
opposite way. The sun's intensity is 3.0, or 4.5 with the sky.

The game overrides the record per level: story levels and `arena1`–`7` use an
indoor preset (no sun, sky or fog, black background). The outdoor arenas
`arenao1`–`5` get sunlight, a sky, fog (about 1 km) and randomised weather.
Elsewhere, "auto" lights a sun only when the level has no lights at all.
Exarust applies the presets and the ambient colour (`exa_world::environment`).
For the outdoor sky it uses Bevy's physically based atmosphere lit by the
level's sun, standing in for the original's sky shader, which is not decoded
(`Enable sky` is an engine option). The time of day and the weather are not
done yet.

## Starts, characters and placed objects

**Player starts** (`exa_world::start`). Facing convention: yaw gives a local
+Z of (sin yaw, 0, cos yaw), and characters face their matrix's Z row.

- New game in `exanima01`: hard-coded at about (81, 0, 39.2) m. The
  "unknown" background wakes lying, facing yaw 150°; the other backgrounds
  start at (82, 2.1–3.0, 39.2) with yaw −50°.
- Arena hub: (0, 0, 3) facing −Z. Old `arena`/`arenae`: (0, 0, 5) facing −Z.
- Arena matches: a centre per arena (`arena1` (0,0,3), `arena3` (−3,0,3),
  `arena4` (−15,0,−4.5), `arenao3` (9,0,1), `arenao5` (8,0,1), …; see the
  code). Fighters stand on a ring of radius min(0.5·teams·size + 1, 3.5) m,
  each facing the centre. Per team t of k: spread = 2(k−1)/(k+1),
  a = 6t/N − spread/2 + m·spread/(k−1), θ = 2π(3 − a)/6,
  position = centre − r·(sin θ, 0, cos θ). In a duel the player stands 2 m
  along +Z.
- Level transitions: the arrival marker in the new level's placed objects.
  It is an objdb class `0x8000AC07` box whose flags' low byte is `0x40`, with
  +0x18 = the previous level's id (from `locales.rdb`, which is the level
  list) and +0x14 = the entrance number. The player gets its matrix;
  followers stand at offsets (−1,0,−1), (1,0,−1), (0,0,1.5), (1,0,2) m in its
  frame.

**Characters (`CAC00001`)**: `i32 n`, an optional local character database
(`CECDDB00`, an RDB with magic `0xDBACCD00`), then n × `CAC0CA00`. Each is
`u32 id` (low 28 bits = record; `0x40000000` = world database), `f32 pos[3]`
(cm), `f32 yaw`, `i32 condition` (`0xA00` = dead, placed from its pose), then
sub-chunks: `CAC0EB00` pose as a bone tree (per node a 3×4 matrix, a word
and a child count), `CAC0E100` legacy flat bone matrices, `CAC0EA00` motion
state, `CACE0F77` AI home (saves). `exanima01` places 39 characters, 8 of
them corpses. Hostility comes from each record's roles in `charroles.rdb`.

Character records (`0x00CDACvv`, the low byte the version; framed as tag +
size, the record ends at its size): name[16], surname[16], physique f32×2,
height (−1…1, positive is shorter), age (0…1), skin colour u16×2, hair
style, hair colour u8×4, face styles u16×2 (read by every version),
voice[16] (`xx0N` gives voice number N − 1), pitch, profession (bit 0
female, byte 1 race), last locale, four held items {id, flags}, then the
worn items: `i32 n` and n × {id, flags}. Ids with `0x80000000` refer to the
level's own object database (`DBC0` → `DBDB`, an RDB of item records like
`objdb.rdb`'s). Across the 29 levels, all 477 placed characters have a
record and 908 of their 979 worn items resolve locally (`exa-tool corpus
levels`). Exarust spawns every race in its own body with its own moveset
(see `races.rdb` in OTHER.md). Only the human frame is physical and
dressed, and dead bodies of other frames are not shown yet.

The rest of the record, in order (versions 5–7 alike up to the inventory):

| field | type | meaning |
|---|---|---|
| feral level | f32 | 0…1: how far gone an undead is (weaker, looser, undead voices); 0 for the living and every non-human race |
| pools | u16 ×3 | yellow (current health) and red (the ceiling it heals to) as shares of the maximum, and focus; share = value / 65535 |
| seed | u16 | random at save |
| combat skill | f32 | 0…100, the AI's skill |
| undead voice | u32 | which undead voice set a feral character uses |
| traits | u8 ×4 | value + 100 (−100…100); the AI reads the second and third |
| search seed | u32 | read by the AI's search activity |
| experience | i32 | multiples of 5000 in the levels |
| (word) | u32 | always 0 |
| skills | `i32 n`, n × {u16 slot, u16 points, u8 k, k bytes} | six slots: Close Combat, Ranged Combat, Armour, Shields, Insight, Concentration; byte i = the technique chosen at level i (1-based id, at most six); one level per 5000 points |
| inventory | `i32 n`, n × {u32 item, u32 flags, u32 ?} | carried items |
| roles | v7: `u32 count`, `u32 len`, len bytes | count × {u32 role, f32 weight, u8 flags (bit 0 explicit), u8 inherited count, u8 n, u8 pad, n × u32 variables}, newest first |
| relations | v7: table, then `i32 m` × {8 bytes, table} | table = `i32 n`; if n ≥ 1: n × {character, offset}, `i32 len`, blob; none in the shipped data |
| saved state | `i32 n`, n × {u32 tag, u32 value} | `CECC0001` heal pool (f32 red still to heal), `CECC0002` potion expiry (game clock) |
| sub-chunks | {u32 tag, i32 size, payload} to the record's end | `CDEC01`/`CDEC02` powers: u32, ten u32 slots, `i32 n`, n × {u32 id, u32 flags; with flag `0x10000000` an `i32 size` and size − 4 bytes}; `CDEC00` and `CDEC12` never occur |

Versions 5 and 6 (the legacy reader) differ after the inventory: roles are
`i32 n`, n × {u32 role, u32 ignored}, each added in turn (with its parents
from `charroles.rdb`), except that a first role of 13 (Disposition), 27
(XA_Proctor) or 22 (Skeleton - Wait) is replaced by 8 (Corpse), 26 (XA
Undead Bandit) or 9 (Skeleton), each followed by 33 (Activity Wait);
relations are skipped (version 5: `i32 n` × 16 bytes, `i32 m` × {8, `i32 k`
× 16}; version 6: a table, then `i32 m` × {8, table}, all skipped);
powers are 16-byte entries. Every placed character's record is version 7;
24 unplaced records in the levels are versions 5 and 6, as are 14 of the 21
arena actors in `actors.rpk` (each actor file is one record followed by its
own item database).

**Techniques and perks.** The original turns the learnt techniques into the
perks its combat and body read: Close Combat 1–4 Remise, Feint, Fend,
Riposte; Armour 5 Security; Shields 1–6 Counter, Synchrony, Ward, Persist,
Endure, Mobility; Insight 6 Iteration; Concentration 1, 5, 6, 8 Sustain,
Abstraction, Clarity, Volition. Close Combat 5–8 (Draw, Impel, Brace, Dual
Wield) give none (the first three are marked unavailable; 37 level records
learn Dual Wield). Armour 1–3 are the Manoeuvring in Armour tiers: the
armour builder takes the highest learnt and lowers encumbrance by 0.3 per
tier; Armour 4 is Deflection (worn coverage up: OTHER.md, Armour and
Encumbrance). The name table has a
seventh skill, Meditation, without a slot or techniques.

**Saving.** The save writes yellow and red as round(value / max × 65535)
(red 0 when not positive), focus × 65535, the seed as 0xFFFF (a random
one when a body is released) and the saved-state entries; the load sets
yellow and red to max × stored value / 65535 and focus to stored value /
65535. Its saved-state loop reads the last entry's value for both tags
(harmless with one entry; with both, the heal pool gets the potion's
expiry), a quirk left to the save system to decide.

Evidence: REA on both record readers, the inventory and relation readers,
the technique routine, the armour builder, the save hook and load, and the
skill and technique name tables; every record of the 13 level databases
(478 version 7, 20 version 6, 4 version 5; 26 deleted entries and two
stubs that are not records) and of `actors.rpk` parses to its end

living placement stores full pools, and every living human is feral (0.4,

**Stats derived at spawn** (`exa_formats::character_stats`). The spawn
runs the character builder, then registers the body (its last call is the
character's init), then the armour pass (which sums the encumbrance:
OTHER.md, Encumbrance), the reach pass and the load of the pools. From the record (h its height, kept within −1…1; f its feral
level, kept within 0…1) and its race (or the built-in record):

| stat | rule |
|---|---|
| body scale | min(race scale, 1.5) × (1 − 0.05·h): a dynamics factor (limbs' muscles 1.25 × it, √scale in turns and reach), not a mesh scale |
| size | race size × (1 − 0.05·h): held weapons' reach and the unarmed hands' stiffness (OTHER.md, Weapon record) |
| standing pelvis | 109.5 − 11.25·h cm over the floor (the spawn places the body at it less 8 cm) |

| locomotion clock | × 1/(1 − 0.1·h) |
| most energy | 1, or 1 − 0.1·f |
| step reach | 80 cm·√scale·(1 − 0.3·f)·(1 − 0.2·encumbrance), with the armour pass's encumbrance (the reach pass runs after it) |
| support pins' factor | race `0x60`, less 0.25·f² when feral (every earlier race-byte value is overwritten) |
| head | pose gain × (1 − f), muscle factor × (1 − 0.8·f) |
| walking arms | 0.2 − 0.15·f, at least 0.05 (the arms in the walk and run cycles) |
| sprint gait | the race's sprint row moved toward its jog by f (OTHER.md, Races) |
| perception | race `0x110`, or 1 − f/2 when feral |
| voice | pitch: the record's within 0.9…1.07 (race byte 7, the hulking ghoul, 0.85); volume: scale × race `0x1B4`; attack-voice step: race `0x1C4` − 1, or 1 when feral |
| clip-rate base | race `0x5C` |

Maximum health is 0.25 × the race's health factor, then by race byte (the
record's, which also picks the race): 3 (ogre) 1.5 and 4 (Sir) 1.0 unless
a golem; golems (bit `0x10` of the byte) 0.5, byte 17 (the boss) 1.0; then
2 (ancient), 6 (ghoul) and 9 (manipulator) 0.375, 5 (Fael) 0.75, 7 and 8
(hulking ghoul, gobbler) 0.5. Only the manipulator differs from 0.25 × its
race's factor (0.375, where its factor 1 gives 0.25). Yellow and red start
at the maximum and the load sets them to the saved shares (× 1.5259022e-5).
The placement reader first sets both pools full when a living placement's
record stores red 0: the arena's opponents and proctor store 0/0 and spawn
full.

The init's rule bits (the body's rule word):

| bit | set for | read by |
|---|---|---|
| `0x1` | creatures (race bytes 3–9), race second word bit 0 | the held-item pass (no fist sphere), the AI |
| `0x2` | living humans not feral, creatures | bandages and potions |
| `0x4` | over half feral, creatures, second word bit 1 | the AI only |
| `0x8` | feral humans, skeletons, ancients | damage: blows take no red health |
| `0x10` | living humans not feral and first word bit 3, in the story | the AI manager's revival |
| `0x20` | ogre and Sir, first word bit 7, second word bit 2 | red regeneration, when `0x100` is clear (OTHER.md, Regeneration) |
| `0x40` | ogre and Sir, first word bit 5 | damage: a quarter of the daze, no swing stall |
| `0x100` | golems (first word `0x3000`, by the armour pass) unless they wear their kind's core (item 500 for `0x2000`, 431 for `0x1000`; every placed golem does) | blocks red regeneration |

Feral levels clear `0x2` and `0x10` and set `0x8`. In the story levels the
97 living humans spawn with most energy 0.9 (×47), 0.9158 (×21), 0.95
(×27), 0.9576 and 0.9602, support pins 1.0 to 1.21, no head gain for the
47 at f = 1, and rule bits `0xC` (×68) or `0x8`; every one of the 451 living
characters spawns at full health. Exarust's body reads the most energy, the
head's gain and factor, the walking arms and the scale (RSQ.md, Physical
body); its held weapons and fists are held by its size, scale and
encumbrance (OTHER.md, Weapon record); the player and the duellist spawn
from a new human record.

Evidence: REA and `exe.asm` on the builder, the init, its head setup, the
body tick's walking arms and energy cap, the spawn's call order, the
placement readers and the readers of the rule bits; corpus tests over
every placed character and arena actor (`exa_formats::character_stats`,
`exa-tool characters`).

**Placed objects (`DBC0` → `DBCE`)**: `i32 n`, then n × `DB01`. Each is
`u32 node id` (`0x80000000` = local objdb `DBDB`, `0x40000000` = world
objdb), `u32` placement flags (version `0x3D23`), `u32` object flags, a 3×4
matrix (cm), container slot, a field, and sub-chunks for articulated or
deformed parts. `exanima01` has 1888, all in the world (slot 0). Exarust
spawns each as a static model, its item's model from `Objects.rpk` or
`Objlib.rpk` (1763 in `exanima01`, none missing). Scripted (`@`) objects and
model-less triggers or markers are skipped.

Bits 16–23 of the placement flags word are the object's condition byte c.
For items whose model section sets bit 0 (`OTHER.md`, object database), the
voxel lights directly under the model's root shine at k = (1 − c/255)² of
their intensity, and the meshes directly under it have their emissive colour
scaled by the same k (REA on the object builder and the material uniforms).
The menu's salve has c = 0; one of `exanima02`'s has `0xEE0000`, a share of
0.0044, nearly spent.

## Props (`3DE10000`)

`u32 count`, then one chunk per prop (`3DE10100`):

```
u32  flags
char object[16]       an Objlib entry
f32  matrix[12]       3×4 placement (cm); replaces the object's root transform
u32  parent           1-based prop index, 0 = level root
u32  ?
sub-chunks            0x3DE0EC00, 0x3DE0ECAC, 0x3DE0ECDB (not decoded)
```

All 79 935 props in the 29 retail levels name existing Objlib objects.

**Flags** (REA on the original's prop reader): `flags & 0xB80000` is copied
onto the object's root node. **`0x80000` places the prop static**: every
node under it is marked too, so none of its rigid bodies registers and its
meshes are level collision (`Prop::STATIC`). Shipped: 0 ×76 045, `0x80000`
×3 883, `0x100000` ×2, `0x180000` ×1, `0x200000` ×4 (lanterns; meaning not
traced); never `0x800000`. `0x3DE0EC00` holds, per child node, a name and
a matrix that replaces the child's local transform (an articulated prop
posed in the editor).

- Base bodies: `humanbase`, `ogrebase`, `golembase`, `demona01base`,
