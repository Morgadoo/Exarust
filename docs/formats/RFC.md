# Chunk trees (`.rfc`): meshes, materials, levels

Status: **verified** for the container, scene node headers, static meshes
and material texture layers (`exa_formats::rfc`, `exa_formats::material`).
Level sections are still **observed** only.

Evidence: the reader in `Exanima.exe` 0.9.5 was examined with REA (Ghidra
12.1.4), and `cargo exa corpus meshes` decodes all **23 065** mesh records in
7 653 retail files with 0 failures. Sample exports (props, a door frame, a
chest, a weapon part) checked in a glTF viewer at real-world sizes.

## Container

```
u16 sanity   0xAFCF
u16 version  0x3D23 (retail); 0x3D21 on 3 meshes in Characters.rpk
chunk*       root chunks until end of file

chunk: u32 tag, u32 size, u8 payload[size]
```

Root chunks: `0xBA00` material list, `0x3D000000` scene node list, and in
level files `0x3DED` tile grid, `0xDBC0` local database (items, strings,
placement), `0x3DE10000` props, `0xCAC00001` characters, `0xEC00DC00`.
Unknown root chunks are skipped by size.

Counts follow two conventions: list chunks (`BA00`, `3D000000`) store the
count; counts inside a mesh store **count − 1**.

## Material list (`BA00`)

`u32 count`, then `count` chunks (`BA01`): `name[16]` followed by a material
payload. The same payload is the value of an entry in an `.rml` library.

Payload: a 184-byte block of shading parameters (not decoded yet), then
56-byte texture layer records:

| off | field |
|---|---|
| 0 | `u32` slot flag |
| 4 | `u32` record length (56) |
| 8 | parameters (layer amount, tint, …) |
| 40 | `name[16]` texture entry, sometimes with `.rfi`/`.dds` |

| slot flag | role (from texture-name suffixes) | uses |
|---|---|---|
| `0x00020000` | diffuse (`d`) | 7 284 |
| `0x00200000` | normal (`n`) | 6 733 |
| `0x01000000` | gloss (`g`) | 4 771 |
| `0x00800000` | height (`h`) | 2 126 |
| `0x00040000` | specular (`s`) | 1 588 |
| `0x08000000` | ? (names without suffix) | 1 572 |
| `0x00100000` | reflection (`r`) | 1 237 |
| `0x00400000` | detail / second diffuse | 261 |
| `0x00080000` | emissive? | 44 |

7 639 of 7 648 payloads follow this layout; 9 material lists in level and set
files do not and are reported. 88 % of referenced texture names exist in the
retail packs; the rest are absent from the shipped data.

Materials are looked up by name: the file's own list first, then the
libraries named in `Exanima.rfp` (`common`, `underworld0`, `underworldb`),
plus `humanbase.rml` for characters. Weapon parts carry no materials (their
look is generated by the weapon factories).

## Scene nodes (`3D000000`)

`u32 count`, then one chunk per node; the chunk tag is the node kind:
`0x3D03` mesh, `0x3D06` and `0x3D0C` light-like nodes, `0x3D08`, `0x3D0A`,
anything else a plain node (`0x3D01`).

Header, shared by every kind:

```
char name[16]
u32  flags         top 20 bits stored; low 12 bits are a class id (0x89 for meshes)
u32  flags2
u32  instance      non-zero: the node reuses other data and stores nothing more
u32  parent        1-based index into the node list; 0 = root
f32  matrix[12]    3x4 row-major: three rotation rows, then translation (cm)
f32  extent[3]
f32  centre[3]
f32  radius
u32  ?
```

The body depends on the kind; after it come optional sub-chunks
(`0x3AC1`, `0x3D0CEC05`, `0x3DD0B001` collision body, `0xEDC0C589`) that are
skipped for now.

## Mesh body (`3D03`)

```
u32 ?                         only when version > 0x3D21
u32 streams - 1
stream × streams:
  u32 id                      low 16 bits are the key used by index maps
  u32 format                  bits 16..23: F3 vec3, F2 vec2, B4 rgba8, A4 skin
  u32 count - 1
  element[count]
chunk 0x3DC0 topology:
  u32 ?
  u32 vertices - 1            unified vertex count V
  u32 groups - 1
  group × groups: u32 ?, u32 first_vertex, u32 last_vertex, char material[16]
  u32 maps - 1
  map × maps: u32 key, index[V]          u16 when V < 65535, else u32
  chunk 0x3DC1 triangles (optional):
    u32 ?
    u32 triangles - 1
    index[3 × triangles]                  into unified vertices
    per group: u32 first_triangle, u32 last_triangle   (empty group: last = first - 1)
    sub-chunks: 0x3DC2 u8[triangles], 0x3DC3 u32[triangles]   (not decoded)
```

| stream id | format word | content | count |
|---|---|---|---:|
| `0x00000001` | `0x00F30001` | positions | 23 065 |
| `0x00000010` | `0x00F20010` | texture coordinates | 23 064 |
| `0x04000001` | `0x02B40100` | RGBA8 vertex colour (channel order unverified) | 2 708 |
| `0x04000001` | `0x02A41000` | skin: 4 × u32 bone, 4 × f32 weight | 113 |

Index maps link each unified vertex to an element of every stream whose id
has the same low 16 bits: key `…0001` → positions (and the colour/skin
streams), `…0010` → texture coordinates. Key `0x0002` has no stream: it
groups vertices for normal smoothing. Normals are not stored. Exarust
computes them by area-weighted accumulation per smoothing group.

Orientation: floor modules (`gefs_*`) lie at y = 0 with every horizontal face
pointing +Y under right-handed, counter-clockwise winding, and floor modules
are 300 × 300 units. Geometry is therefore centimetres, right-handed, Y-up,
CCW fronts, the same as glTF after scaling by 0.01. Mirroring relative to the
running game has not been checked yet.

Textures pair with texture coordinates unchanged when images keep their
stored (bottom-up) row order.

## Level (`3DED`) — observed

Tile-grid dungeons are assembled from modular sets in `Resource.rpk`:
`gews_*` (wall sets, `TGEWallSet`) and `gefs_*` (floor sets,
`TGEFloorSet`).

```
u32  n_wall_sets;  char name[16] × n     "GEWS_UWA01"
u32  n_floor_sets; char name[16] × n     "GEFS_WodPlA1"
u32  grid_w, grid_h                      32, 32
u32  ?                                   0
u32  cell_size?                          600
u8   cells[grid_w * grid_h][12]          per-cell wall/floor/flags
```

Large outdoor-style levels (`arenao*`, `exanima05..08`) have a companion
`.rft` terrain with the same base name.

## Level and set naming

- Story levels: `exanima01..08`, `exanima67` (+ `_c1`, `_sw` variants),
  `exanimac1`; arenas: `arena`, `arena1..7`, `arenae`, `arenahub`,
  `arenao1..5`; `menuscene` is the title scene.
- Base bodies: `humanbase`, `ogrebase`, `golembase`, `demona01base`,
  `skelbase`, `wraithhabase`, `gobblerbase`, … with `*morph.rfc` morph sets.
