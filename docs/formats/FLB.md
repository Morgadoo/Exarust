# Shader libraries (`.flb`)

`Resource.rpk` carries two shader libraries: `shading.flb` (54 programs: the
surface, light, ambient, fog, reflection, GI and effect programs) and
`textures.flb` (61 procedural texture generators). `exa_formats::flb` parses
and decodes them; `exa_render::shader_template` expands their text and
`exa_render::shader_program` chooses the program and its flags.
`exa-tool shader` prints the result for a material (`--shader-library
textures.flb --list` lists the procedural texture programs).

## Container

The table of contents is the pack layout (`docs/formats/OTHER.md`, packs):

| offset | type | field |
|---|---|---|
| 0 | u32 | magic `0xAFBF0C01` |
| 4 | u32 | table bytes, a multiple of 32 |
| 8 | 32 × n | records |
| 8 + table | — | data blob |

A record is `name[16]` (NUL-padded, not terminated at exactly 16),
`offset: u32` **relative to the blob start**, `length: u32`, then eight
zero bytes. Names are compared exactly, so `{$lights}` finds `lights`.

## Cipher

Every entry is decoded on its own; the key restarts at `0x2BCBE389`:

```
key = 0x2BCBE389
for each little-endian u32 word of the entry:
    key = key * 0x10A860C1 mod 2^32
    r = (key >> 13) & 31
    if ((key >> 13) & 7) == 0: r |= 4
    plaintext = rotate_left(ciphertext, r)
```

Only whole words are decoded (`length / 4`); shipped entries are padded to a
multiple of four. The engine then trims up to three trailing NUL bytes and
hands GLSL a NUL-terminated string, so an embedded NUL ends the program. The
parser keeps that text and returns an error, never a panic, on a bad magic,
a misaligned table, an out-of-bounds entry or a short header.

## Template language

The builder walks one entry once per variant:

- `#version 150\r\n` is prepended unless the entry starts with `#`.
- `{$name}` includes another entry of the library, expanded in place (its
  loop stack and flags are shared). `{$Interface}` is generated by the
  engine. An unknown include is dropped silently.
- `{?cond?} … {?END?}` takes the block when `cond` holds;
  `{?ELSE?}` and `{?ELSE cond?}` give alternate branches (an else-if chain).
  `!` negates a term. `&` joins terms.
- `{%LOOP count variable initial%} … {%END%}` repeats the body `count −
  initial` times, the variable (one character) counting from `initial`.
  `count` is a decimal number or an integer variable, optionally minus a
  digit (`DspSdws-1`). A non-positive count skips to the matching end without
  running the body. Nested loops count.
- `{%expr%}` writes an integer expression; `{%i%}` is a loop variable.
  `{% .x %}` (a dot command) writes `.x`; this form is not used by the
  shipped programs.
- `{%DspSdws%}`, `{%1/DspSdws%}` etc. are expressions.

Whitespace right after any marker is dropped, so the newline after a command
is removed and the next template line joins the previous output line. Only
when nothing but whitespace follows is the run copied.

### Conditions

The builder scans a term up to a space or `?`, records a `.` member and a
`[i]` index, and matches:

- `Mat.Name`, `Shd.Name`, `Obj.Name`, `Env.Name`: a flag field, tested
  `>= 1` alone, or compared with `> d` / `= d` (one digit).
- `Light[i].Direct` and `Light[i].Sky`: the light's kind in the object's
  light list, by the bracketed index (a digit or a loop variable).

Names not in a table (`UseDither`, `Shd.DispSdwF`, the `zShd.` typo in
`shadetrl`) are false.

The integer variables are `Lights` (the object's light count, 0–6),
`SdwSmps` (shadow taps per sub-frame), `ShadeQual` (0–3, `quality − 3` held
at 0 and 3) and `DspSdws` (4 when `DispSdw`, else 0).

The `&` chain reproduces the builder's loop: it takes the value of the term
after the `&` and, when that holds, evaluates the same term once more before
looking for the next `&` or the closing `}`. A false term before the `&` is
therefore forgotten; only `Lights > 0 & Light[0].Direct` relies on the
chain, where the second test implies the first.

### Expressions

Tokens are numbers, loop variables or integer variables. Operators `* + - /`
apply strictly left to right (no precedence), ending at `%`. The quotient
reads a token one byte short of the operator (its zero-length first token
still parses its first digit). An integral result prints as an integer; a
fraction prints in general form with three significant digits, so the one
shipped fractional expression `1/DspSdws` prints `0.25`. No shipped
expression divides by zero.

### Interface

`{$Interface}` expands per stage.

**Vertex**: the `Global` block; `in vec3 vNrm` / `out vec3 vrNrm` when
`Shd.UseNrm`; `in vec3 vDlt` when `Obj.VrtDlt`; `in vec4 vCol` /
`out vec4 vrCol` when `Obj.VrtCol`; `in vec2 vTex` and `out vec2 vrTex`
(or `vriTex` with a height map) when the material has any texture; a
`VrtCldr` uniform when the object word asks; `int PassIdx` for a
quad-rendered deformed object.

**Fragment**: `vrNrm`, `vrCol`, the texture coordinate varying, `NrmTex`
(and `vrTng` when `Shd.TngtNrm`), `DifTex`, `EmiTex`, `SpcTex`, `OpcTex`,
`GlsTex`, `DspTex` (height map or `DispSdw`), `DrtTex`, `vec2 vrTex` (with
a height map), the `Global` block, `EnvMap` (lit or specular), `LqdLvl`
(spot lights), `VXGIPos` and `VoxelGI` (voxel GI), one shadow sampler per
light (`Shadow0` is a `sampler2DShadow` for a spot or directional first
light, a cube otherwise; later lights always cubes, and a directional first
light adds `in vec3 vrSdw`), `FrmBuf` for specular materials, `int PassIdx`
for quad rendering, and `uniform vec3 SdwSmp[4·SdwSmps]` (or `SdwSmps`)
for lit materials.

Every declaration ends `;\r\n`, and the `Global` block itself ends
`};\r\n` (252 bytes, `docs/RENDERING.md`).

## Programs and permutations

A material's record is packed into a **shader word**. Its low nibble picks
the program:

| nibble | fragment program | vertex |
|---|---|---|
| 0 | `shading_f` (legacy) | `shading_v` |
| 1 | `shadeopt_f` (PBR) | `shading_v` |
| 2 | `shading_f` (unlit) | `shading_v` |
| 3 | `shadehar_f` (hair) | `shading_v` |
| 5, 6 | `shadesss_f` (skin) | `shading_v` |
| 7 | `shadetrl_f` (translucent) | `shading_v` |

The material type gives 0→0, 1→1, 2→2, 3→3, 4→6. A non-zero subsurface
colour lifts the class to 5 at shading quality 3 and above; the translucent
mode (`kind & 0x300 == 0x100`) wins with 7. The selector is: 7 →
translucent; 4 → subsurface; `& 7 == 3` → hair; `& 1` → PBR; else legacy.
Grass (`shadegrs_f`), smoke (`shadesmk_f`), the terrain (`shadetrn_f/v`)
and the effect programs are chosen by their own draw paths, not this word.

Other shader-word bits:

- `BlendMode` = the render class's bits 12–14;
- `DirtMode` = 4 (blood) for extra flag `0x4000` with a diffuse map, else 1
  (grime), 2 or 3 from extra bits `0x7000` when the record has a dirt layer;
- `AlphaTst` when the class has `0x4000` and there is a diffuse or opacity
  layer;
- `TngtNrm` when a normal layer exists (tangent-space; the object-space
  layer parameter is not decoded);
- `DispSdw` at shading quality 5 with extra `0x100000`;
- `FastLgt` below shading quality 5;
- `UseNrm` (the mesh's normals; every lit surface reads `vrNrm`);
- `LocalRef` (screen-space reflection); the warm-up clears it below
  shading quality 5.

`SdwSmps` is the shadow quality's `2^(shadow quality − 1)` taps, split over
the supersampling level `L` as `2^max(q−1, L−1) / 2^(L−1)`, never below one.
At shadow quality 4 and the original's 4× supersampling that is 2 taps per
sub-frame; at no supersampling it is 8.

The material key masks the record's feature bits with `0x09FE0B1F` and the
extra flags with `0x43CB7F`; the plug-in mask per type is `0x01FE001F`
(0), `0x09FE031F` (1), `0x00400018` (2), `0x09FE001F` (3, 4).

### Warm-up

The game precompiles 29 common combinations while its shaders warm up
(`WARMUP` in `shader_program`), skipping rows whose displacement shadows
need quality 5 or height map needs quality 4. Each lit row compiles once
per light count 0–6; the environment word gains `0x100 << 2i` per light.
`exa-tool shader --warmup` lists the keys.

## Uniform blocks

### `Global` — std140, 252 bytes

| offset | field | value |
|---|---|---|
| 0 | `ViewPos` | camera eye (cm), `w` = the frame's time delta |
| 16 | `ViewSiz` | viewport width, height (one less when multisampled) |
| 24 | `ViewPrj` | `tan(fov/2)·500`, `aspect·tan(fov/2)·500` |
| 32 | `CamMat` | camera view-projection, column-major |
| 96 | `SdwMat` | the sun's world-to-shadow matrix |
| 160 | `VXGIScl` | `1/(W·20)`, `1/(H·20)`, `1/(D·20)`, `1/SdwSmps` (texels across X, Z, up) |
| 176 | `Ambient` | linear level ambient × exposure × 15, `w` = 8 indoors or 3 outdoors |
| 192 | `TimeDlt` | `(Δt, −Δt)` |
| 200 | `ViewRcp` | `1/width`, `1/height` |
| 208 | `FogColr` | linear fog colour, `w` = `1/fog distance` |
| 224 | `FogPos` | the fog plane's position (rule not decoded) [guess] |
| 240 | `BufrPos` | the frame-copy offset for refraction |
| 248 | `Wetness` | the environment's wetness |

### `Material` — std140, 112 bytes

| offset | field | value |
|---|---|---|
| 0 | `MatDif` | linear diffuse (×1.5 before linearising for type 0) × opacity if the blend source is ONE × `(1 − sss)`; `w` = opacity minus the fall-off's `(f+1)f` |
| 16 | `MatSpc` | linear specular × specular level, zero without the specular bit, ×3 for a PBR program with a specular map; `w` = glossiness (raised to 0.01 only for type 0) |
| 32 | `MatEmi` | linear emissive × exposure (×2 for a lit material with an emissive map); the skin path uses the diffuse × sss, `w` = the secondary colour's `w` + 1 |
| 48 | `MatDrt` | mode 4 `(0.45, 0.03, 0.02, 0.5)`; else `w = 2 − 0x30` |
| 64 | `MatDsp` | parallax texel counts × 3·10⁻⁵ |
| 72 | `DrtUVs` | the diffuse map's aspect |
| 80 | `OpcFll` | `(sign, 1.8·exponent, (f+1)·amount, refraction)`, both negated with extra flag `0x100` |
| 96 | `DspSdw` | `(0x5C·0.004, 1 + 0.125·subpass, 0x60·0.05, 0)` |

### Lights

Each light is three `vec4`s:

- `[3i]`: position (cm) or direction, `w` = the shadow map's depth scale;
- `[3i+1]`: linear colour × intensity × 2/π ÷ `SdwSmps` × `(1 − dimmer)` ×
  exposure, `w = 0.8/radius`;
- `[3i+2]`: `x` = `(softness + 1)·0.005` (0.003 with `FastLgt`; a
  directional light takes `softness·0.5·0.005`), `yzw` = the vertical
  shaping or `(1,1,1)`.

The shader adds `SdwSmps` shadow comparisons, which is why the colour is
divided by the tap count; attenuation is `max(1 − 0.8d/R, 0)⁴`, the
vertical factor
`max((2^(z(ly + (1−ly)y)) − 1)/(2^z − 1), 0)`.

## Evidence and open points

The container, cipher, marker language, flag tables, integer variables,
program selector, warm-up table and UBO values come from the executable's
shader builder and material factory; the templates and their permutations
are cross-checked by expanding every entry of the installed library. Open:

- `UseDither` and `Shd.DispSdwF` have no table entry: always false.
- `Light[i].Sky` is registered beside `Direct`; its use is unconfirmed.
- The float formatter's output beyond the shipped `0.25` is a three
  significant-digit general format [guess].
- `FogPos`, the light depth-scale denominator and the `0.125` term of
  `DspSdw.y` are not fully decoded [guess].
- `OpcFll`/`DspSdw` are written at half precision by the engine; the parser
  keeps `f32` values.
- Object-space normal maps (the layer parameter's `0x10` bit) are treated as
  tangent-space.
- The skin class test reads the shading quality itself (≥ 3), not the
  `ShadeQual` lift; the shipped quality 5 applies it.
