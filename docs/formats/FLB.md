# Shader libraries (`.flb`)

`Resource.rpk` carries two shader libraries: `shading.flb` (54 programs: the
surface, light, ambient, fog, reflection, GI and effect programs) and
`textures.flb` (61 procedural texture generators). `exa_formats::flb` parses
and decodes them; `exa_render::shader_template` expands their text,
`exa_render::shader_program` chooses the surface program and its flags, and
`exa_render::texture_program` builds a `textures.flb` entry as its own
fragment program with the fixed `MPrj` projection.
`exa-tool shader` prints the result for a material (`--shader-library
textures.flb --list` lists the procedural texture programs).

## Container

The table of contents is the pack layout (`docs/formats/OTHER.md`, packs):

| offset | type | field |
|---|---|---|
| 0 | u32 | magic `0xAFBF0C01` |
| 4 | u32 | table bytes, a multiple of 32 |
| 8 | 32 × n | records |
| 8 + table | — | data blob |

A record is `name[16]` (NUL-padded, not terminated at exactly 16),
`offset: u32` **relative to the blob start**, `length: u32`, then eight
zero bytes. Names are compared exactly, so `{$lights}` finds `lights`.

## Cipher

Every entry is decoded on its own; the key restarts at `0x2BCBE389`:

```
key = 0x2BCBE389
for each little-endian u32 word of the entry:
    key = key * 0x10A860C1 mod 2^32
    r = (key >> 13) & 31
    if ((key >> 13) & 7) == 0: r |= 4
    plaintext = rotate_left(ciphertext, r)
```

Only whole words are decoded (`length / 4`); shipped entries are padded to a
multiple of four. When the last byte is a NUL the engine trims up to four
trailing NULs; the expander walks the rest by its length, embedded NULs
included, and GL reads the finished program up to its first NUL (no
shipped entry has an embedded NUL). The parser returns an error, never a
panic, on a bad magic, a misaligned table, an out-of-bounds entry or a short
header. Decoded with `exa-tool shader --dump DIR`, all 54 `shading.flb`
entries match, byte for byte, an independent decode of the installed
library.

## Template language

The builder walks one entry once per variant:

- `#version 150\r\n` is prepended unless the entry starts with `#`.
- `{$name}` includes another entry of the library, expanded in place (its
  loop stack and flags are shared). A name starting `Interface` (nine
  characters are compared) is generated by the engine. An unknown include
  is dropped silently.
- `{?cond?} … {?END?}` takes the block when `cond` holds;
  `{?ELSE?}` and `{?ELSE term?}` give alternate branches (an else-if chain).
  `!` negates the first term. `&` joins terms.
- `{%LOOP count variable initial%} … {%END%}` repeats the body `count −
  initial` times, the variable (one character) counting from `initial`.
  `count` is a decimal number or an integer variable, optionally minus a
  digit (`DspSdws-1`). After the subtracted digit the builder's cursor stays
  on that digit, so a variable written after it would be read one character
  early (the blank); no shipped loop combines the two. A count below one
  pass skips to the matching end without running the body. Nested loops
  count.
- `{%expr%}` writes an integer expression; `{%i%}` is a loop variable.
  `{%.i%}` (a dot command) writes `.x`, `.y`, `.z` or `.w` for the value.

Whitespace right after any marker is dropped, so the newline after a command
is removed and the next template line joins the previous output line. Only
when nothing but whitespace follows is the run copied. A command also
consumes the CR/LF pairs right after its `%}`.

### Conditions

The builder scans a term up to a space or `?`, records a `.` member and a
`[i]` index (a digit or a loop variable), and matches by the term's first
four characters:

- `Mat.Name`, `Obj.Name`: the flag field, true when, read as a signed
  integer, it is at least 1. There is no comparison: a following `= d` is
  left to the chain, which reads it as a further term and fails.
- `Shd.Name`, `Env.Name`: the same test, unless an `=` follows anywhere
  between the term's end and the marker's `}`; then the field is compared
  with the digit two characters after the `=`. (So in `A & B = 2` the first
  term would take the second's comparison; no shipped condition does
  this.) There is no `>` on flags.
- A bare name is an integer variable: `> d` and `= d` compare with one digit
  (its byte minus `'0'`); alone, the variable's truth test answers.
- `Light[i].Direct` and `Light[i].Sky`: false unless `i` is below `Lights`;
  `Direct` is the slot word's `0x300` bits equal to `0x200` (a light whose
  node type bits are clear: the sun, with its 2D shadow map; the level's
  point lights store `0x100`); `Sky` is simply `i = 0`.

The integer variables and their truth tests:

| variable | value | alone |
|---|---|---|
| `Lights` | the object's light count, 0–6 | false (no test) |
| `SdwSmps` | shadow taps per sub-frame | more than one tap, or super-sampling on |
| `ShadeQual` | shader-word bits 20–21 | false (no test) |
| `DspSdws` | displacement-shadow taps per sub-frame | above zero |

The chain: the first term (negated by `!`) is read; at a `}` it is the
value. At an `&` the next term is read **without** its `!`; false ends the
chain false, true reads that term again (with its `!`) and goes on. A false
term before an `&` is therefore forgotten; only `Lights > 0 &
Light[0].Direct` uses the chain, where the second test implies the first.
An `{?ELSE term?}` reads a single term, with neither `!` nor `&`.

### Expressions

Tokens are numbers, loop variables or integer variables. A token starting
with a digit is read as digits for its whole length. Operators `* + - /`
apply strictly left to right in single precision (no precedence), ending at
a blank or `%`. The quotient reads its left token one byte short (its
zero-length first token still parses its first digit). A result within
0.0001 of its truncation prints as that integer, digit by digit: one digit
below 10 (`'0'` plus the value, so a negative value prints a character
below `'0'`), two below 100, three otherwise. Any other result prints with
the engine's float printer: three decimals cut from the fraction digit by
digit in single precision, the last one rounded to nearest (ties to even),
a carry rippling into the integer part, trailing zeros trimmed but one kept
after the point (`1/4` → `0.25`, `1/3` → `0.333`, `1/16` → `0.062`).

### Interface

`{$Interface}` expands per stage.

**Vertex**: the `Global` block; `in vec3 vNrm` / `out vec3 vrNrm` when
`Shd.UseNrm`; `in vec3 vDlt` when `Obj.VrtDlt`; `in vec4 vCol` /
`out vec4 vrCol` when `Obj.VrtCol`; `in vec2 vTex` and `out vec2 vrTex`
(or `vriTex` with a height map) when the material has any texture; a
`VrtCldr` uniform when the object word asks; `int PassIdx` for a
quad-rendered deformed object.

**Fragment**: `vrNrm`, `vrCol`, the texture coordinate varying, `NrmTex`
(and `vrTng` when `Shd.TngtNrm`), `DifTex`, `EmiTex`, `SpcTex`, `OpcTex`,
`GlsTex`, `DspTex` (height map or `DispSdw`), `DrtTex`, `vec2 vrTex` (with
a height map), the `Global` block (unless shader-word bit 31), `EnvMap`
(lit or specular), `LqdLvl` (the liquid material mode, `0x300` bits
`0x200`), `VXGIPos` and `VoxelGI` (voxel GI), one shadow sampler per light
(`Shadow0` is a `sampler2DShadow`, with `in vec3 vrSdw`, when the first
slot is directional, a cube otherwise; later lights always cubes),
`FrmBuf` for specular materials, `int PassIdx` for quad rendering, and
`uniform vec3 SdwSmp[4·SdwSmps]` (or `SdwSmps`) for lit materials. A
geometry-stage compile expands no interface. A surface's fragment entry is
`<set>_f`, and the builder only appends `_f` while the set name is shorter
than 15 characters.

Every declaration ends `;\r\n` (an indexed one carries its index, one or
two digits, first), and the `Global` block itself ends `};\r\n` (252 bytes,
`docs/RENDERING.md`).

## Programs and permutations

The material factory builds two words from a record: the **material
word** (`Mat.` flags) and the **shader word**, whose low nibble picks the
program:

| nibble | fragment program | vertex |
|---|---|---|
| 0 | `shading_f` (legacy) | `shading_v` |
| 1 | `shadeopt_f` (PBR) | `shading_v` |
| 2 | `shading_f` (unlit) | `shading_v` |
| 3 | `shadehar_f` (hair) | `shading_v` |
| 5, 6 | `shadesss_f` (skin) | `shading_v` |
| 7 | `shadetrl_f` (translucent) | `shading_v` |

The selector is: 7 → translucent; bit 2 → subsurface; `& 7 == 3` → hair;
bit 0 → PBR; else legacy. Grass (`shadegrs_f`), smoke (`shadesmk_f`), the
terrain (`shadetrn_f/v`) and the effect programs are chosen by their own
draw paths, not this word.

`exa_render::material_state` keeps the type table: the five built-ins
above with their masks and base classes, a reset to them (the factory's
start-up hook resets it each time it runs, dropping plug-ins), and
`MaterialTypes::register`, which resets an empty table first and appends a
plug-in at index 5 and up. A record picks its type by the low byte of its
kind word. The factory list beside it is ordered by the low nibble of each
record's flags, a new record going after those of the same or a higher
priority; a material calls every record whose mask meets its plug-in mask
(payload `0x94`), in that order. The default builder's record serves masks
1 and 4.

The factory starts from the record's loaded feature bits: its flags
(`0x48`), plus `0x800` for a positive fall-off amount, the slot bit of a
loaded diffuse, opacity, height, gloss, `0x4000000` or dirt layer, and
`MatEmi` for an opacity-only record without lit bits; masked by the type's
plug-in (`0x01FE001F` type 0, `0x09FE031F` 1, `0x00400018` 2, `0x09FE001F`
3 and 4). With no lit, specular or emissive bit left, a record with an
opacity above zero draws as emission only (material word `0x8`), otherwise
nothing. The shader word starts at the plug-in's class (0, 1, 2, 3, 6).
Then, each bit needing its feature bit (and, for a map, its layer):

- material: two-sided; `MatDif`/`MatAmbDif` from the lit bits; `OpctFall`
  when the fall-off amount's magnitude exceeds 0.01; `MatSpc`; `TexDif` for
  a lit record with a diffuse (or opacity) layer; `TexOpc` with the opacity
  bit and that layer, or with the emissive map; `TexEmi` with `MatEmi`;
  `TexSpc` with `MatSpc` or `TexRef` (the layer and `0x100004`); `TexRef`;
  `TexNrm` with the layer and a shaded material word (`0x100807`); `TexGls`;
  `TexDsp` for a height layer with a positive amount and a normal map;
  `DrtTex` (`0x8000000`); the translucent (`0x100`) and liquid (`0x200`)
  modes from the flag bits `0x300`. A type-2 plug-in keeps only
  `MatEmi`, two-sided and `TexOpc`, so it can bind only the colour/opacity
  slot; the emissive map also needs `MatEmi`, so a type-2 record never binds
  it;
- a secondary (subsurface) colour at shading quality 3 or above: class 5
  and material bits `0x300`, and no `MatEmi`;
- shader: `FastLgt` from extra flag `0x200` (lit records); `BlendMode` 4
  when the render class's low nibble is 4; `NegNdL` from extra `0x400`
  (specular records); `AlphaTst` when the diffuse bit, a diffuse (or
  opacity) layer, the opacity bit and the class's `0x4000` meet; `LocalRef`
  from extra `0x800` above shading quality 4 with a reflection layer;
  `TngtNrm` for a normal layer whose parameter word lacks `0x10` (else the
  map is object-space); `UseNrm` whenever the material word has any of
  `0x100807`; `DispSdw` from extra `0x100000` above quality 4 with a height
  layer and a normal map; `DirtMode` 4 (blood, the built-in speckle) for
  extra `0x7000` = `0x4000` with the diffuse bit, else 1, 2 or 3 for
  `0x0`, `0x1000`, `0x2000` with a dirt layer (another value binds the map
  but sets no mode); the translucent mode sets class 7 and `NegNdL`.

The program key keeps the material word's `0x09FE0B1F` bits and the
shader word's `0x0043CB7F` bits, then adds the quality bits: `ShadeQual`
`= quality − 3` from quality 4 in bits 20–21 (wrapping past 6 in its two
bits) and `FastLgt` below quality 5. The environment word is the scene's
(GI `0x10`, tone map `0x4`, sharpen `0x8`, specular GI `0x80` at quality 6
with GI, the level's fog and outdoor bits), less `VXGISpec` for a program
with `FastLgt`, plus each light slot's word shifted two bits per slot.

`SdwSmps` is the shadow quality's `2^(q−1)` taps (at most 32), split over
the super-sampling setting `L`: with `l = L` for `L ≤ 1` and `l = L−1`
otherwise, it is `2^max(q−1, l) / 2^l`. At shadow quality 4 and the
original's 4× setting (`L = 3`) that is 2 taps per sub-frame; without
super-sampling it is 8. The object word carries `SdwSmps − 1` from bit 24
(not masked) and `0x1000` with super-sampling on. `DspSdws` is 0 without
`DispSdw`, otherwise 4 over the setting's factor (1, 2, 3, 4, 8, 15 for
settings 0–5), at least 1: 4 without super-sampling, 1 at the 4× setting.

`exa-tool shader <library> --all` lists every record's key words and
program; in the four shipped libraries all 30 records with a reflection
layer (metals, glass, eyes, skin) keep `TexRef`.

### Warm-up

The game precompiles 29 common combinations while its shaders warm up
(`WARMUP` in `shader_program`; the table matches the executable's), skipping
rows whose displacement shadows need quality 5 or height map needs quality
4. The row's words are used as stored (quality bits added, `LocalRef`
dropped below quality 5), `DspSdws` takes its value whatever the row, and
each lit row compiles once per light count 0–6 with `0x100 << 2i` per
light in the environment word (unlit rows have an empty one).
`exa-tool shader --warmup` lists the keys.

## Uniform blocks

### `Global` — std140, 252 bytes

| offset | field | value |
|---|---|---|
| 0 | `ViewPos` | camera eye (cm), `w` = the frame's clock × exposure |
| 16 | `ViewSiz` | viewport width, height (one less when multisampled) |
| 24 | `ViewPrj` | `tan(fov/2)·500`, `aspect·tan(fov/2)·500` |
| 32 | `CamMat` | camera view-projection, column-major |
| 96 | `SdwMat` | the sun's world-to-shadow matrix |
| 160 | `VXGIScl` | `1/(W·20)`, `1/(H·20)`, `1/(D·20)`, `1/SdwSmps` (texels across X, Z, up) |
| 176 | `Ambient` | linear level ambient × exposure × 15, `w` = 8 indoors or 3 outdoors |
| 192 | `TimeDlt` | `(clock·exposure, −exposure/factor)`, the factor the super-sampling setting's 1–15 |
| 200 | `ViewRcp` | `1/width`, `1/height` |
| 208 | `FogColr` | linear fog colour, `w` = `1/fog distance` |
| 224 | `FogPos` | the midpoint of the camera's eye and the sun camera's eye (`eye + (sun − eye)·0.5`); `w` is not written |
| 240 | `BufrPos` | the frame-copy offset for refraction |
| 248 | `Wetness` | the environment's wetness |

### `Material` — std140, 112 bytes

| offset | field | value |
|---|---|---|
| 0 | `MatDif` | linear diffuse (×1.5 before linearising for type 0) × opacity if the blend source is ONE and the record is not in refraction mode (`0x300` = `0x200` in the plug-in-masked word), × `(1 − sss)`; rgb is zero on an unlit record; `w` = the stored opacity minus the fall-off's `(f+1)f` whenever the fall-off exceeds 0.01 (the factory's test for blended states compares a four-bit field with `0x100` and never holds) |
| 16 | `MatSpc` | linear specular × specular level, zero without the specular bit, ×3 when the shader word's bit 0 is set (classes 1, 3, 5, 7) and the material word has a specular map; `w` = glossiness (raised to 0.01 only for type 0) |
| 32 | `MatEmi` | linear emissive × exposure (×2 when the plug-in-masked word keeps `MatEmi` `0x8`, the lit/specular bits and the emissive-layer bit `0x80000`); a record whose material word has the translucent or refracting mode bits (`0x300`) is not scaled by the exposure; the skin path uses the diffuse × sss, `w` = the secondary colour's `w` + 1 |
| 48 | `MatDrt` | mode 4 the material record's dirt tint (`+0x248` of the runtime record: a spawned weapon writes `(1.0, 0.06, 0.04, 0.3)`, the hair record `(0.45, 0.03, 0.02)`); else `w = 2 − the record's dirt strength` |
| 64 | `MatDsp` | parallax texel counts × 3·10⁻⁵ |
| 72 | `DrtUVs` | the diffuse map's aspect |
| 80 | `OpcFll` | `(sign, 1.8·exponent, (f+1)·amount, refraction)`, both negated with extra flag `0x100` |
| 96 | `DspSdw` | `(0x5C·0.004, 1 + 0.125·PassIdx, 0x60·0.05, 0)` |

A record in the liquid mode (`0x300` = `0x200`) also binds a refraction
background to the screen-copy unit: without the scene's own refraction
texture it loads the built-in `BkgRfr01` for an opacity up to 0.85 (a NaN
takes this branch) and `BkgRfr02` above it; with one, the scene's low
(`+0x6C`) and high (`+0x64`) fields. Any other record binds the scene's low
field when it has an opacity map and the scene has the texture.

### Lights

Each light is three `vec4`s:

- `[3i]`: position (cm) or direction, `w` = the shadow map's depth scale;
- `[3i+1]`: linear colour × intensity × 2/π ÷ `SdwSmps` × `(1 − dimmer)` ×
  exposure, `w = 0.8/radius`;
- `[3i+2]`: `x` = `(softness + 1)·0.005` (0.003 with `FastLgt`; a
  directional light takes `softness·0.5·0.005`), `yzw` = the vertical
  shaping or `(1,1,1)`.

The shader adds `SdwSmps` shadow comparisons, which is why the colour is
divided by the tap count; attenuation is `max(1 − 0.8d/R, 0)⁴`, the
vertical factor
`max((2^(z(ly + (1−ly)y)) − 1)/(2^z − 1), 0)`.

## Evidence and open points

The container, cipher, marker language, flag tables, integer variables and
their truth tests, number printing, program selector, factory rules, warm-up
table and UBO values come from the executable's shader builder, material
loader and factory (checked in the assembly where the pseudo-code is
ambiguous: the signed flag tests, the `=` scan, the chain's `!`, the
rounding modes). The decoded entries match an independent decode byte for
byte, and every entry expands without leftover markers. No capture of the
programs the running game compiles was made, so whole expanded programs are
checked through these rules, not against a dump. Open:

- `UseDither`, `AddPass`, `BaseNrm` and `Shd.DispSdwF` have no table entry:
  always false. The procedural texture code swaps in its own variable and
  object tables (`Layers`, `Layer[i].Masked`). `exa_render::texture_program`
  expands each of the 61 texture entries (as its own fragment program, with
  the surface fragment interface), pairs it with the built-in vertex shader
  the draw state's stream word selects, binds the attributes by name
  (`vPos` 0, `vTex` 1, `vNrm` 2, `vCol` 3, `vTx2` 4, `vTng` 6, `vDlt` 7)
  and uploads the `MPrj` matrix; Exarust bakes the textures on the CPU, so
  no entry is drawn.
- The loader passes the feature bits through a factory method before the
  plug-in mask; it is taken as the identity [guess].
- The factory's quality field is taken as the shading-quality setting and
  its extra shader bits as zero [guess].
- A record type past the five built-in plug-ins is taken as type 0 [guess:
  no shipped record has one].
- `FogPos` was read from the builder: it lerps the camera's eye and the sun
  camera's eye at 0.5 with the engine's `a + (b − a)·t` helper, in single
  precision. The light depth-scale denominator is the light's far radius
  times the scene's light scale, and `DspSdw.y` adds `0.125·PassIdx` to 1,
  both from the writer's own instructions.
- The material record's dirt tint (`+0x248`) is a field of the runtime
  material, not of the 184-byte library block; Exarust's record reader has
  no value for it and the uniform writer takes the caller's tint (zero for
  a record on which nothing wrote one).
- The height layer's parallax pass reads the height texture: a map one
  texel tall clears the material word's `0x800000` and the shader word's
  `0x100`, and only the height takes part in that test (a one-texel width
  still displaces).
- `OpcFll`/`DspSdw` are written at half precision by the engine; the parser
  keeps `f32` values.
- During the warm-up the light slots keep whatever the last draw left in
  them; Exarust takes them as point lights.
