# `exa_formats`

Engine-independent parsers for the formats inside the packs. Each takes
bytes and returns plain data or an error. No Bevy dependency.

**Phase:** 0–1. Spec and status per format: [`docs/formats/`](../../docs/formats/README.md).

| module | status |
|---|---|
| `kind` | format detection by magic for every shipped entry |
| `chunk` | `.rfc` chunk framing and list chunks |
| `rfi` | images: header, mip chain, the registered block formats (BC1, DXT1a, BC3, DXT5n/na, BC4 luminance/alpha plane, the RGB-only LATC, BC5) decoded with the original's bit replication and truncating blends, the blue-first and ZYX uncompressed orders (through the `pixel` converters), RLE unpacking, the header flag word (stored chain, repeat per axis, the two-bit texture detail class, the cube bit) and the first uploaded mip level the detail setting picks; a level's and a face's size from the format word's block/packed/channel fields, cube faces with a chain each, the converters' pixel count, and owned image data with the original's copy, base-only copy, create, render-target, resize, release and whole-image conversion |
| `palette` | the dye palette: 32 families (hue, saturation, base value, step), the linear and lifted HSV ramps in the original's precision, and the lifted colour as the factory stores it in bytes |
| `procedural` | the 25 procedural materials: family, passes, colour/specular/normal texture lists and wear weight; the random material sets, finish levels, colour classes, default finishes and emblem ids (the item roll shares the sets and classes); emblem picture names |
| `pixel` | the original's 20 pixel formats (ids, fallbacks, sizes), the four channel-order formats it registers separately (BGR8, BGRA8, ZYX8, ZYXV8), and its converters between them: grey, alpha, grey-alpha, two-channel with Z rebuilt, 1-bit, RGB, RGBA, blue-first and ZYX sources, luma, the float formats; the byte/float conversions its mipmapper picks per format word (linear, squared colour, centred) |
| `rdb` | database index |
| `uid` | the mutable id-keyed database object and its sorted id→offset index: find by id, record views, in-place payload replacement (hole closed, offsets fixed), loading with the expected-magic check and upgrade hook (a mismatch clears the table), and the index's insert, find, delete and block store (a block's first word is its length, itself included); nothing in the game reads the index yet |
| `locales` | `locales.rdb`: an id found by its 16-byte name (ASCII case ignored) and a record's 16-byte name copy |
| `colour` | the engine's Rec. 601 luma in its accumulation order and its float and 8-bit desaturation (the sRGB curves are `exa_assets::human_skin`'s, the HSV conversion is `palette::rgb_to_hsv`), and the packed RGBA8 store: red-first unpacking, the round-to-even saturating channel byte (the integer indefinite stores zero), RGB/RGBA packing with the opaque-alpha form, the scalar and per-channel scales and the two-colour blends in byte units |
| `roles` | roles (`charroles.rdb`): head, init script, variables and entries with their sections (the corpse script where the original reads it), the dialogue graphs of role entries and `narrator.rcd`; a level's locale in `locales.rdb`; the shared held-role list (`HeldRole`, add/remove, the stored 12-byte-word read) both the AI and the scripts use |
| `races` | races: names, flag words (bleeding, red regeneration, claws, hovering, quadruped), the look word (skin texture set, hair, beard, age darkening), body model, movesets, health, natural armour, the body scalars (clip-rate base, size, scale, mass divisor) and the body controller's factors, the gait table with its brake distances and the feral sprint blend, the stats (unarmed reach, weapon swing-turn and recovery factors, AI attack bonus, perception, held offset, footsteps, voice), the two voice templates as the runtime race expands them and the voice-set names built from them, and the executable's built-in record a missing id falls back on |
| `character_db` | the local and world character databases: id-sorted binary lookup, lazily parsed shared records with holder counts and the database tag in their id, first-free-id allocation, adding (live, no bytes until a flush), release by the record's tag, delete, payload replacement (in place at the same length, else appended), re-serialisation of live records, the `0xDBACCD00` save and load, and a reader for a save's RDB chunk |
| `characters` | a level's placed characters (position, facing, condition, saved pose, a save's motion state and AI home) and their records read whole, versions 5–7 (level databases and `actors.rpk`): the bone-tree pose as depth-first records (world frame, word, child count) and the legacy flat frames per slot; looks (physique, height, age, skin, hair, face, voice number, pitch, sex, race), held and worn items with their flags, feral level, saved pools, seed, combat skill, undead voice, traits, search seed, experience, the six skills with their techniques, inventory, roles with their stored weights, relations and per-level relation tables, saved state, loadouts, the reserved words and powers; the record written back byte for byte (voice rebuilt from its number by the game's formatter, names one byte per character, traits converted as the game's SSE instruction does, five techniques at most, powers and the reserved pair only when set), copied through the writer, the constructor's and the creator's defaults (focus 0; the reset also in place, with the underwear), the record's own technique check, the perks the learnt techniques give, the Manoeuvring tier and Deflection; an actor's own item database |
| `character_stats` | the stats a record and its race spawn with, as the original's builder and init derive them: body scale and size by height, standing pelvis, leg reach, most energy, step reach, support pins' factor, the undead's head gain and factor and walking arms, sprint gait, perception, voice, maximum health with the race-byte rules, health from the saved pools (in double precision), the body rule bits, the init's race presets (balance bonus, arm relaxation, footstep volume, golem footsteps) as a table over the race record's values; Deflection and the encumbrance the armour pass sums;
the attack reach (√scale × (1 − 0.3 age) × (1 − 0.2 encumbrance) × 80 cm) |
| `encumbrance` | a character's encumbrance as the original's armour pass sums it (worn items' bytes, articulated pieces, Manoeuvring tiers, the floor, the held shield with Mobility, the golem suit, the cap, and the second wind a kind-2 worn item grants), the special-kind dispatch over the worn items (`WornSpecials`: second wind, the healing, golem-suit and gauntlet effects in wearing order with their crystal bytes, the mind ward, the focus charm's regeneration) from a record and the databases its ids name, and the factors it gives the reach, run, sprint, turn, steps and get-up clock |
| `rfc` | scene nodes (meshes, lights, voxel lights, cameras, sectors; box, rigid body, cloth marker, the static node flag, the instance that owns a node (with `Scene::mesh_of` resolving its owner's mesh), keyframe tracks after any kind's body, a mesh's morph set, unknown chunk tags and the `ChunkHandlers` node sub-chunk registry) and static meshes with their position-stream count and smoothing keys (all retail meshes decode); generated normals are the sum of unit face normals over each smoothing key weighted by the original's corner-angle approximation, accumulated per position element in the incidence's order, split into smoothing-key runs by the original's swap partition (and the cloth pass's unweighted variant is `Mesh::recompute_flat_normals`) (faces flagged `0x10000` only for a key nothing else reaches); bounds refit from the vertices, triangles regrouped by material and appended (`Mesh::merge`), the shadow pass's cull-front render flag, a point's barycentric coordinates on a face, and the face record (`Face`: unit normal, plane, corners, edge and area terms) with the queries built on it: closest point, one-sided ray hit (strict and inclusive), a sphere's push-out, a swept sphere's first touch and a point's distance to the nearest face, walked over a mesh (`Mesh::{faces, ray_hit, ray_hit_inclusive, sphere_hit, swept_sphere_hit, within_hit}`); the local database with its object records, placed objects and string table, read whole or on its own |
| `rfc_write` | the original's level export: chunk framing (open, close, take back out), the walk that sorts and numbers nodes, props, placed objects and characters, and every chunk it writes (grid, materials with the texture renames, nodes with mesh, light, voxel light, rigid body, cloth, emitter, GI points and keyframe tracks, props and part records, the local database, characters with pose, AI home and motion state, environment); the save game's placement writer and the save-level wrapper that appends the story settings chunk |
| `morph` | morph sets (`*morph.rfc`: landmarks, base positions, targets; both shipped sets decode), the physique weights a record gives them, the transfer to body parts and garments (nearest surface within 10 cm, the nearest landmark's offset, neighbour fill) and morphing a scene's meshes, bounds and joints |
| `key_track` | node keyframe tracks (`0x3AC1`): play mode, duration, keys of time and position (the one shipped track decodes) |
| `rigid_body` | models' rigid bodies: class, mobility, rest tetrahedron, point masses, collision spheres, links (pins, ropes, sliders with their travel), scrape and roll sound slots (every body of every pack decodes) |
| `material` | material payloads: every word of the 184-byte block (the named shading parameters and the words with no reader kept whole), texture layers and slot roles, the texture load flags (`0x54`), the subsurface colour (`0x6C`), the dirt amount (`0x30`), the refraction word, the render-state and plug-in words, the physical divisor a rigid body's mobility is divided by, the voxel GI's thin-mesh rule (class bit `0x4000`, or an opacity layer with opacity above 0.75), the impact sound prefix and the UV transform builder; the constructed object's `0x700F0` load word and divisor 1, and the built-in `_Default` grey with its never-freed reference count; the constructed object's `0x700F0` load word and divisor 1 and the built-in `_Default` record |
| `flb` | shader libraries: the pack table of contents, the per-entry rotation cipher, the decoded GLSL entries and their total error rules ([FLB.md](../../docs/formats/FLB.md)) |
| `objdb` | the object database: each tier held as the original's table over one payload blob (binary search and insertion, payload store and deletion, the writer, so a loaded database writes back byte for byte), the upgrade of the `0xDBAC0D08`/`0D07`/`0D06` layouts (operative; weapon; and for `0D06` the body with its paint seed and the random-table condition words), the section chain and its editing routines, table flags, the three id tiers with tagged lookup and first-free ids, header and model fields, the string resolver (none, inherit the parent's, an own tier string or the shared library), the template clone, instancing, local duplication, the item dispatcher, promotion to the world tier with container children and the id and link remap tables, both removal routines, template migration (body, appearance with the material sets, condition refresh of protection and value, weapon, container, door, model), the item-use test and the class-0 use action, the experience table, the random-table condition word, the quantised item fields and the amount helpers; and the decoded item fields: names, models, occupancy, appearance, the trade rank word and armour type, protection, burden (encumbrance, covered bones, articulated set, special kind, powered), the model section's `0x24` byte, which the equip conflict pass reads as an equip lock and an item panel counts as the entry's bulk, weapon, shield, door, operative (including a teleporter's symbol atlas and destination level ids) and container sections (`Item::container`, its panel size, capacity, item limit and children) and the random table (`Item::random_table`), and the mechanism a record makes of its model |
| `objstrings` | the object string library (`objstrings.rdb`, a level's `0xDBCD` library): one-based ids, reference counts, Latin-1 text, the original's allocator (free hint), setter (in place or hole closed and appended), add-reference and release, clear, and the writer (byte for byte) |
| `trade_record` | the shop fields of an item record: listing word, parent id, the model's rarity tier, rarity and size words, and the rank by body, weapon or shield ([Trade fields](../../docs/formats/OTHER.md#trade-fields)) |
| `weapon_stats` | weapon stat bytes and how a factory recipe and the item's condition produce them (the blade, head, guard and haft rules with both deform curves and their double-precision terms, the flipped side's bonuses, byte wrapping and caps) |
| `weapon_record` | the record a held weapon fights with (all 28 elements, the holding pass and the equip refresh), whether its section defines a flipped side, its length along the model's rigid parts (stopping at the first non-rigid one) and its sweet spot, the built-in fists and claws by race, the race's weapon fields from its decoded stats, the mass table the part-tree redistribution reads, the shield record, the part's shield stat block and the step reach |
| `rsq` | skeleton, bodies and motion set of `humanoid.rsq`; the moveset tree (parents are the nearest earlier moveset of their name) and a character's clip table from a base moveset and the held items' config word (`MotionSet::assemble`, `MovesetConfig`: the weapon moveset under each ancestor, then the Torch and Flaming overlays) |
| `hw_config` | the hardware configuration: the settings screen's graphics, audio and input options with their ranges, defaults, slider steps and labels, the GPU benchmark's measurement protocol and quality tiers, the Deck preset, the settings file lines Apply writes, key names and the hardware startup settings ([UI.md](../../docs/UI.md#settings-options), [SETTINGS.md](../../docs/formats/SETTINGS.md#the-settings-screens-options)) |
| `settings_ini` | the user settings file: the registry of 41 named, typed settings, the `Name = value` reader with its conversions (integer, boolean, fraction, RGB/RGBA colour), the graphics, window and hardware rules and defaults (GUI size, quality clamps, frame cap, the aim-speed step, volume and the game's tips and checkpoints), the `KeyDef` hotkey macros, the settings screen's and the game's line rewriters, the number formats and the user folder and file names |
| `settings_store` | the binary settings store: nested `{tag, size}` chunks addressed by tag paths, get, set with the enclosing sizes kept, the integrity check and the empty-store rule; the key bindings' path |
| `save_package` | the retail save package: magic, sentinel and 24-byte directory, `0x2000`-aligned 16-byte-named sections with the original's placement (last strictly larger gap after any entry, the sentinel included; moved when the room is short; offset recomputed from the entry before on every write) and directory-only delete, writes that keep the bytes read (gaps, deleted payloads and the old tail; never truncating), the slot file names (prefix cut to fifteen bytes) and scanner number, the 52-byte story/arena `#playerdata` headers, the character placement (reference, position, heading, condition, sub-chunks), the writer's chunk order for both modes, the reader's defaults (default journal, global worth 0, memory 0, zero transition) and first-chunk character rule, tagged chunks, masks, journal, world database sections and version rules; the in-memory reset of a short or wrong-magic file on open (nothing written until a section is), and the checkpoint/save name swap |
| `text` | the engine's text and number helpers: popcount and signed floor-log2, a substring search from an offset, decimal and two-digit integers, hex with a width, the fixed-point float formatter (truncating fraction digits, a tie-to-even last digit, carry through nines, trimming), parsers for decimal, float and hex, the fixed 16-byte name type with its length, ASCII lowering, zero-string and ANSI text (the 0x85 ellipsis past sixteen), offset writes and appends, extension replacement and C-string export, the sixteen-byte, bounded and ANSI compares (plain, case-insensitive and the mixed form that lowers only the second text; the case-insensitive ANSI compare falls back on the length difference), the ANSI-string lowering that never reaches the last byte, the zero-string compare, forward and backward byte searches, the buffer splice, the byte-reversed performance-counter seed, the truncating fraction, three-byte numbers, hex colours, the a/an test and title-casing |
| `save_chunk` | the save game's settings chunk and the save curve, the version gate and record table, the save number (including the original's `00` for a negative), the mode words, the slot order/number/insert/delete rules, the permadeath (health below 0.01 in double) and checkpoint rules, and the game clock (signed tick difference) |
| `arena_save` | the arena career's own save chunks: the company, day, tournament, employees, merchant, shop-stock, item-list/arsenal (25 lists, shelf by shelf with its boxes inside), hub-stash and hireables payloads, with a character codec for the hireables, the arena table writer's chunk order and reader (the reader's table-chunk test), and the load's list compactions (drop top-bit markers, remove a special entry's later duplicates, then every eight-byte list and the twelve-byte list in the repair's order); an old save's repair of the player's record compacts its worn list, each loadout's worn list and its carried items (top-bit ids dropped) before the record's re-derive |

| `file_ref` | file plumbing: the folder table, file references with inline names, entry stems, extension swaps, the folders made for a path, the search path, whole-file reads and writes, and the file-format registry |
